## 2. 主力機實際裝了什麼

### 2.1 必要（缺了就不能改程式碼）

| 套件 | 這台的版本 | 安裝來源 / 路徑 | 誰在用 | 缺了會怎樣 |
|---|---|---|---|---|
| macOS | 26.1（25B78）、**arm64** | — | — | 專案本身跨平台，Linux/Windows 都行 |
| .NET SDK | **10.0.302**（host 10.0.10, osx-arm64） | 官方安裝檔，`/usr/local/share/dotnet` | 全部 `dotnet` 指令 | 完全不能建置。`net10.0` 不能用 8/9 跑 |
| Git | 2.39.5（Apple Git-154） | Xcode Command Line Tools | 版控、`data` 分支操作 | 不能 clone / push |
| GitHub CLI `gh` | 2.97.0 | `brew install gh` | 看 Actions、觸發 workflow、讀 secret 清單 | 只是不方便，網頁可代替 |

沒有 `global.json`，所以 SDK 版本不會被釘住——**裝更新的 .NET 10.x 沒問題**，
裝 9 就會失敗（這台同時留著 9.0.101，是別的專案在用，跟本專案無關）。

NuGet 套件（`dotnet restore` 會自己抓，不必手動裝）：
`Npgsql 10.0.3`、`xunit 2.9.3`、`Microsoft.NET.Test.Sdk 17.14.1`、`coverlet.collector 6.0.4`。
`dotnet test` 應該是 **36 個測試全過**。

### 2.2 選配（只有在本機做特定事情時才需要）

| 套件 | 這台的版本 | 安裝來源 / 路徑 | 只有做這件事才需要 |
|---|---|---|---|
| `libpq`（提供 `pg_dump`） | **18.6** | `brew install libpq`，`/opt/homebrew/Cellar/libpq/18.6/bin/` | 在本機備份 Supabase（`scripts/backup-supabase.sh`） |
| `python3` | 3.11.13 | Homebrew `python@3.11`，`/opt/homebrew/opt/python@3.11` | 備份腳本的 GFS 輪替、本機預覽靜態站 |
| `jq` | 1.7.1-apple | **macOS 內建**，不是 brew 裝的 | 把 `db/*.sql` 送進 Supabase Management API |
| `curl` | 8.7.1 | macOS 內建 | 同上 |
| VS Code | — | `/usr/local/bin/code` | 編輯器，換成任何 IDE 都行 |

**`libpq` 有兩個雷，都已經在腳本裡處理掉了：**

1. **它是 keg-only**，`brew install libpq` **不會**把 `pg_dump` 放進 `PATH`。
   這台跑 `which pg_dump` 是找不到的，但備份照樣能跑——
   [backup-supabase.sh:21](../scripts/backup-supabase.sh#L21) 會自己去 `/opt/homebrew/Cellar/libpq/*/bin/` 撈。
   要指定別的路徑就設環境變數 `PG_DUMP`。
2. **`pg_dump` 的版本不可以比伺服器舊。** Supabase 是 PostgreSQL **17.6**，
   這台是 18.6（比較新，可以）。用 16 會直接 `exit 1`，不是警告。
   GitHub Actions 的 runner 內建 16，所以 workflow 裡有一步專門裝 17。

### 2.3 這台有、但**不要**跟著裝的

| 套件 | 為什麼在這台 |
|---|---|
| `gcc`、`python-tk@3.11`、`unar` | 使用者其他專案在用，跟本專案無關 |
| .NET SDK 9.0.101 | 同上 |
| Docker | **這台沒裝。** 只有想在本機試「還原備份」才需要，而週日的 workflow 已經自動在做 |

## 3. 憑證與權限（逐項）

### 3.1 GitHub

| 項目 | 這台的實際狀態 | 權限範圍 | 影響什麼 |
|---|---|---|---|
| SSH key | `~/.ssh/id_ed25519`，`origin` 是 `git@github.com:qwe953751/Investment.git` | 該帳號對 repo 的寫入權 | `git push`。不想設 key 就改用 HTTPS（見下） |
| `gh` 登入 | 帳號 `qwe953751`，OAuth token（`gho_`）存在 macOS keyring | scopes：**`repo`**、**`workflow`**、`read:org`、`gist` | `repo` 給讀寫程式碼與觸發 workflow；**`workflow` 是改 `.github/workflows/*.yml` 必須的**，少了它 push 會被 GitHub 直接拒絕 |
| Actions secret `SUPABASE_DB_URL` | 已設在 repo secrets | 只有 workflow 讀得到，人看不到值 | 每日回補、同步、對帳、備份、盤中收集 |
| Actions 內建 `GITHUB_TOKEN` | workflow 自帶 | `permissions: contents: write` | 推 `data` 與 `gh-pages` 分支 |
| GitHub Pages | 已開在 `gh-pages` 分支 | 公開 | <https://qwe953751.github.io/Investment/> |

**接手的機器要用 HTTPS 而不是 SSH：**

```bash
git remote set-url origin https://github.com/qwe953751/Investment.git
gh auth login          # 選 HTTPS，讓 gh 代管 git 憑證
```

若是用 PAT 而不是 `gh auth login`，fine-grained token 需要：
**Contents RW**（推程式碼）、**Actions RW**（觸發／重跑 workflow）、
**Metadata R**（必選）、Pull requests RW（只有要開 PR 才需要）。
classic token 則是 `repo` + `workflow` 兩個勾。

### 3.2 Supabase

專案 `dehzxlxyfvtnylwgbmqy`，PostgreSQL 17.6。

| 憑證 | 放在哪 | 身分與權限 | 缺了會怎樣 | 到期 |
|---|---|---|---|---|
| `SUPABASE_DB_URL` | 這台的 `~/.zshrc`；CI 在 repo secrets | 寫入帳號 **`invest_writer`**，可讀寫資料，**沒有 CREATE／DDL 權限**，也不是 `postgres` 的成員 | `sync`／`verify`／`status`／`intraday`／`backup-supabase.sh` 直接報錯；其餘功能正常 | 無 |
| `SUPABASE_ACCESS_TOKEN` | 這台的 `~/.zshrc` | Management API，以 `postgres` 身分執行，**足以做 DDL** | 只影響「改資料表」（送 `db/*.sql`），不影響日常任何流程 | **約 2026-09-15**（TODO 6 在追） |
| Supabase anon key | `src/Invest.Web/appsettings.json` | **故意公開**，只有 select（RLS 見 `db/001_intraday.sql`） | — | 無 |

兩點要記住：

- `~/.zshrc` 裡的東西**只有互動式 shell 讀得到**。非互動指令（很多 agent 預設如此）要用 `zsh -ic '...'`，否則會拿不到變數而誤判成「沒設」。
- **anon key 公開是設計，不是疏漏**——它會被發佈到 gh-pages，藏起來沒有意義。
  另外兩個值**永遠不要進 repo**。

## 4. 缺了怎麼補

```bash
# macOS
brew install gh libpq            # jq、curl、python3 系統多半已經有
# .NET 10 SDK 走官方安裝檔：https://dotnet.microsoft.com/download

# Ubuntu / Debian
sudo apt-get install -y gh jq python3 postgresql-client-17
# postgresql-client-17 在預設套件庫可能找不到，要先掛 pgdg 套件庫

# Windows
winget install GitHub.cli Microsoft.DotNet.SDK.10 jqlang.jq
```

補完再跑一次第 1 節的驗證區塊。

## 5. 各裝置做得到什麼

| 裝置 | 改程式碼 | 本機跑網頁 | 本機備份 | 觸發／重跑 workflow | 看網站 |
|---|---|---|---|---|---|
| 主力 Mac | ✅ | ✅ | ✅ | ✅ | ✅ |
| 公司電腦（裝好 .NET 10） | ✅ | 需要行情快取 | 需要 `SUPABASE_DB_URL` + `pg_dump` ≥ 17 | 需要 GitHub 權限 | ✅ |
| iPhone / iPad | 只能用 GitHub 網頁編輯器 | ❌ | ❌ | ✅ 用 Safari 開 github.com | ✅ |

**日常運作不需要任何裝置開機**——回補、同步、備份、發佈全在 GitHub Actions 上跑。
所以接手時**先確認「是不是真的需要在本機跑」**：多數故障只要在 Actions 上重跑就解決了，
那條路完全不需要上面任何一個套件。
