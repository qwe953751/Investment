## 1. 已查證的事實

### 問題 1：颱風假當天，盤中自走鏈空轉

- 10/23 盤中自走鏈跑了 **101 棒**。平常一天 9～12 棒，9/25、9/28、10/09 這些已知假日也都約 9 棒。
  空轉從 10:01 開始，每 3 分鐘一棒，一直到 15:07。
- 機制如下：
  1. 第一棒在 09:00～10:00 收到的都是 10/22 的資料，判定「今天沒有開盤，提早收工」。
  2. 下一棒在「等到開盤」步驟用 `in_session` 判斷，但它只看 `market-calendar.json`，裡面沒有 10/23，所以又開始收集。
  3. 這時已經過了 10:00，只跑 1 輪就收工。「保底停留」把這一棒補到 180 秒，接著換下一棒，如此重複。
  4. 13:35～15:05 的興櫃尾段也一樣：CDN 上沒有今天的快照就結束，再換下一棒。
  - 證據：run `39890035541` 的 log 有「到 10:00 為止 1 輪都是上一個交易日的資料，判定今天沒有開盤，提早收工」。
- 每一棒都會：
  - 對 MIS、證交所、櫃買打約 40 個批次請求
  - 寫一次 Supabase 的交易限制名單
  - 做兩次 alert-clear
  - 開兩個 job

  資料沒有壞，也沒有亮鈴鐺，但這違背使用者在 2026-08-23 的決定：「到 10:00 都沒有，再停掉」。
- 興櫃尾段用的 `IntradaySnapshotPublisher.TryLoadLatestSnapshotAsync` 有兩種情況都回 `null`：CDN 的 `latest.json` 讀取失敗（非 2xx），以及「今天確定沒有快照」。
  所以**不能拿收集器的結束結果當休市訊號**。改用 `market-day` 命令（`TradingDayResolver`）當唯一的判斷依據：
  週末、證交所日曆、MIS 日期在 10:00 後仍停在上一個交易日，三者任一成立就判定休市。
- `TradingDayResolver` 目前**沒有任何單元測試**。
- 完整流程在颱風假不會誤亮紅燈：10:00 之後 MIS 日期不是今天，`market-day` 就回 `closed`，回補整步跳過。
  不過 10/23 三場排程都被 preflight 略過，所以這條路在正式環境還沒有被實際執行過。
- 以下兩點維持現狀，不改：
  - 前端在颱風假會顯示「如果今天休市，那就是正常的」的橫幅，跟國定假日一樣。
  - 下一個交易日的 `backfill` 會把 10/23 寫成非交易日標記，跟 10/09、9/25 一樣。

### 問題 2：用 run 結束時間判斷「今天跑過了沒」

- 判斷「今天跑過了沒」的地方有兩處，都以 run 的 `updated_at ≥ 今天 00:00（台北）` 當作「今天的 run」：
  1. `intraday.yml` 的 `maybe_kick_snapshot`：平日 18:00～22:00 的鬧鐘，條件是「盤後資料對帳」成功。
  2. `daily-snapshot.yml` preflight 的同日檢查：**只列 `event=schedule` 的 run**，條件是正式發布步驟成功。
- 前一晚的 run 跨過午夜才結束，隔天就會被誤當成「今天已完成」，18:00 的鬧鐘因此不叫。真實交易日已經發生過 3 次：

  | 交易日 | 騙到它的 run（台北時間） | 當天行情實際被收的時間 |
  |---|---|---|
  | 9/03 | `33647038773`（9/02 23:12 → 9/03 00:39） | 20:46 那場排程（data 分支歷史已壓縮，以 run 時間推定） |
  | 10/14 | `38425869828`（10/13 23:53 → 10/14 00:17） | 21:42 進 data |
  | 10/20 | `39278618967`（10/19 23:31 → 10/20 00:17） | 21:36 進 data |

  平常是 18:07～18:10 進 data。這 3 次都是第一場晚到的排程用 close-coverage 發現缺口才補回來（log：「盤中已開盤、盤後仍缺失或不完整」）。
  **沒有掉資料，但延遲了約 3.5 小時。** 10/23 也被騙了，鬧鐘 log 寫「今天的 run 39806832165 已通過盤後資料對帳，不重複叫」，但那天是颱風假，沒有影響。
- 跨午夜的 run 主要有兩個來源：
  1. preflight 只看 schedule 事件。18:00 鬧鐘叫起來的完整流程是 `workflow_dispatch`，preflight 看不到。
     最近排程都到 21:3x～23:5x 才送達，每天會再多跑一次完整流程（含 pg_dump 備份），開得晚就跨過午夜。
  2. 10/22 23:39 那場：列表 API 只花 0.44 秒就回「找不到」，平常要 3～6 秒。**原因沒有查證。**
- 10/22 那場（`39806832165`）的「驗證網站盤後日期」是在 `2026-10-22T16:00:01Z`，也就是台北 10/23 00:00:01 才開始跑。
  跨過午夜才跑的驗證，`DueThrough` 仍是 10/22，證明不了 10/23。這就是新規則要以「今天 18:00 之後開始的驗證步驟」為準的原因。
- API 的時間格式是 `2026-10-22T16:00:01Z`（UTC、沒有小數秒）。

## 2. 修正 A：「今天的每日快照完成了沒」改看步驟時間（問題 2）

### 判斷規則

兩處共用這條規則，而且只實作一份。

某一輪 `daily-snapshot.yml`（schedule 和 workflow_dispatch 都算）**同時**符合下列三點，才算「台北日期 D 的每日快照已完成」：

1. 步驟「驗證網站盤後日期」`conclusion == "success"`，而且 `started_at ≥ D 18:00（台北）`，也就是 `D T10:00:00Z`。
   - 這一步跑的是 `close-coverage manifest`。只有 18:00 之後開始跑，`DailyCloseCoverage.DueThrough` 才會包含今天。
     所以這一步成功，才能證明：今天如果有盤中紀錄，今天的盤後行情已經完整，而且在 manifest 裡。
   - publish-only 會跳過這一步，所以純發布不可能被誤認成已完成。2026-08-31 事故（白天的純發布騙過鬧鐘）的防線因此保留。
2. 步驟「發佈到 frank-invest.github.io（單一網址，訪客為預設）」`conclusion == "success"`。
3. 步驟「回補行情」`conclusion` 是 `success` 或 `skipped`。
   - 休市日 `market-day` 判定 closed 時，這一步會被跳過，算完成。
   - 回補撐到 21:00 仍失敗的那一輪不算完成。

在 D 18:00 之前不可能有任何一輪符合，所以 16:07 準時送達的排程照常等到 18:00 收今天的行情，跟現在一樣。

### A1. 新增 `scripts/daily-snapshot-done.mjs`

比照 `scripts/etf-dividends-runs.mjs` 的寫法：export 純函式，檔案被直接執行時才走 CLI。

- `export const DAILY_REFRESH_HOUR = 18;`
  加註解：必須等於 `CollectionSchedule.DailyRefresh`，以及 `DailyCloseCoverage.DueThrough` 裡的 18 點。
- `export const STEP_NAMES = { verify: '驗證網站盤後日期', publish: '發佈到 frank-invest.github.io（單一網址，訪客為預設）', backfill: '回補行情' };`
- `export function findCompletedSnapshotRun({ runs, jobsForRun, businessDate, excludeRunId = null })`
  - `businessDate` 必須是 `YYYY-MM-DD`，否則 throw。
  - `since = Date.parse(`${businessDate}T18:00:00+08:00`)`。固定寫 `+08:00`，因為台灣沒有日光節約；不要用 runner 的本地時區。
  - 先篩候選 run：`String(run.id) !== String(excludeRunId)`，而且 `Date.parse(run.updated_at) >= since`。
    步驟在 18:00 後才開始的 run，`updated_at` 一定也在 18:00 之後，先篩掉其他 run 可以少打 API。
  - 對每個候選呼叫 `jobsForRun(run.id)`，取 `steps = jobs.flatMap(job => job.steps ?? [])`，用上面三點判斷。三個步驟必須在**同一輪**裡都成立。
  - 找到第一個就回傳 `{ done: true, runId, event, verifiedAt }`；都不符合就回傳 `{ done: false, checked: <候選數> }`。
- CLI：`node scripts/daily-snapshot-done.mjs --repository <owner/repo> --business-date <YYYY-MM-DD> [--exclude-run-id <id>]`
  - 參數驗證比照 `etf-dividends-runs.mjs`：repository 或日期格式不對就 throw。
  - 列 run：`gh api repos/<repo>/actions/workflows/daily-snapshot.yml/runs?per_page=100`。
    **不要**加 `event=`、`created=` 這類搜尋篩選，理由見第 1 節 10/22 23:39 那場。不加篩選的最新 100 筆約涵蓋一週半。
  - 取步驟：`gh api repos/<repo>/actions/runs/<id>/jobs?per_page=100`。
  - 判斷完成：stdout 印 JSON，exit 0。
  - 任何 API 或解析錯誤：stderr 印原因，exit 1。
  - **呼叫端把 exit ≠ 0 當成「不確定」，照常執行、照常叫。** 這維持現在「寧可多跑一輪也不要漏收」的方向。

### A3. `daily-snapshot.yml` preflight 的同日檢查

把 `day_start=...` 和整個 `while ... done < <(gh api --paginate ... event=schedule ...)` 換成下面這段，換掉之後保留原本的 `should_run=true` 與「沒有找到……」兩行：

```bash
set +e
result=$(node scripts/daily-snapshot-done.mjs \
    --repository "$GITHUB_REPOSITORY" --business-date "$today" --exclude-run-id "$GITHUB_RUN_ID")
code=$?
set -e
if [ "$code" -eq 0 ] && [ "$(echo "$result" | jq -r '.done')" = 'true' ]; then
    echo "should_run=false" >> "$GITHUB_OUTPUT"
    echo "今天的 run $(echo "$result" | jq -r '.runId') 已在 18:00 後驗證並發布今天的盤後行情，略過這場備援。"
    exit 0
fi
if [ "$code" -ne 0 ]; then
    echo "查不到今天的每日快照紀錄（exit $code），保守起見執行這場快照。"
fi
```

- 判斷順序不變：close-coverage check → 晚到超過 3 小時就略過 → 同日檢查。

  - `GH_TOKEN` 與 `actions: read` 權限已經有了。
  - runner 內建 node 與 jq。
- 更新註解：說明為什麼看步驟開始時間、為什麼納入 workflow_dispatch。
- 改完的效果：
  - 18:00 鬧鐘叫起來的完整流程發布後，晚到的排程會看到它並略過，不會每天深夜再多跑一次完整流程。這是跨午夜 run 的主要來源。

## 3. 修正 B：確定休市後留在本棒，不讓下一棒重開收集（問題 1）

### 規則

收集步驟（盤中或興櫃尾段）**正常結束**，而且現在還沒過今天 15:05 時，問一次 `market-day`：

- **exit 10（確定休市）**：這一棒留下來，睡到「今天 15:05」與「本棒預算到期」兩者較早的那個時間。
  - 本棒預算到期 = `hop-started-at` + `HOP_BUDGET_SECONDS`。
  - 每 10 分鐘再問一次 `market-day`：回 0（MIS 出現今天的日期）就提早結束，交給下一棒收集；回 20 或其他就繼續等。
- **其他結果**（0 開盤、20 不確定、程式出錯）：不留，照現在的方式交棒。
- 這一步**永遠 exit 0**，不讓本棒轉紅，也不影響鈴鐺。

套用到 10/23 的預期：
1. 第一棒 07:38 起跑，預算到 13:08。10:00 判定休市後留到 13:08。
2. 第二棒 13:08 收 1 輪，判定休市，留到 15:05。
3. 第三棒 15:05 起跑，直接睡到下一次開盤。

**101 棒會降到約 3～4 棒。**

正常交易日的行為：
- 13:35 盤中收集結束時，`market-day` 回 0（MIS 已經是今天），照常交棒，多花約 15 秒。
- 15:05 興櫃尾段結束時已經過了時段，直接結束，不呼叫 `market-day`。

已知取捨：判定休市之後如果其實是誤判，最慢要 10 分鐘才會發現。現在則是每 3 分鐘就重開一整棒。
新做法偵測慢一點，但成本只有約百分之一，而且符合使用者「到 10:00 都沒有就停掉」的決定。

### B1. 新增 `scripts/intraday-closed-hold.sh`

- 用法：`scripts/intraday-closed-hold.sh <hold_until_epoch> [check_interval_seconds，預設 600]`
- 只用可攜的 `date +%s` 與 `sleep`，因為 node 測試會在 Mac 上跑。GNU 的 `date -d` 只能留在 YAML 裡。
- 印出時間時用 `date -d "@$t" +%H:%M 2>/dev/null || date -r "$t" +%H:%M`，Linux 與 Mac 都能跑。
- 不要把變數取名叫 `until`，那是 bash 保留字，請用 `hold_until`。
- 骨架：

```bash
#!/usr/bin/env bash
# （註解：10/23 颱風假空轉 101 棒的原因，以及這支腳本的規則）
set -uo pipefail
hold_until=$1
interval=${2:-600}

market_day() {
    dotnet run -c Release --project src/Invest.Web -- market-day
}

if [ "$(date +%s)" -ge "$hold_until" ]; then
    echo "今天的收集時段已過，不必留在本棒。"
    exit 0
fi

market_day
code=$?
if [ "$code" -ne 10 ]; then
    echo "今天不是確定休市（market-day exit $code），照常交棒。"
    exit 0
fi

echo "今天確定休市，留在本棒到 <HH:MM>，不讓下一棒重開收集；每 $(( interval / 60 )) 分鐘複查一次。"
while :; do
    now=$(date +%s)
    [ "$now" -lt "$hold_until" ] || break
    nap=$(( hold_until - now ))
    [ "$nap" -gt "$interval" ] && nap=$interval
    sleep "$nap"
    [ "$(date +%s)" -lt "$hold_until" ] || break
    market_day
    if [ $? -eq 0 ]; then
        echo "MIS 已出現今天的成交日期，結束等待，交給下一棒收集。"
        exit 0
    fi
done
echo "今天的收集時段結束，交棒。"
exit 0
```

- 要設執行權限：`chmod +x`，並用 `git update-index --chmod=+x scripts/intraday-closed-hold.sh` 寫進 git。在 Windows 上作業時尤其要注意這一步。

### B2. `intraday.yml`

1. `- name: 收集盤中報價` 加上 `id: collect`；`- name: 收集興櫃尾段` 加上 `id: tail`。
2. 在 `- name: 更新網站上的警報` 之後、`- name: 保底停留` 之前，新增這一步：

```yaml
      # （註解：2026-10-23 颱風假 101 棒、為什麼用 market-day 而不是收集器的結束結果、
      #  為什麼上限是 15:05 與本棒預算、每 10 分鐘複查）
      - name: 確定休市就留在本棒到今天收集時段結束
        if: steps.wait.outputs.collect == 'true' && (steps.collect.outcome == 'success' || steps.tail.outcome == 'success')
        run: |
          started=$(cat "$RUNNER_TEMP/hop-started-at" 2>/dev/null || echo 0)
          if [ "$started" -le 0 ]; then
              echo "沒讀到本棒開跑時間，不留。"
              exit 0
          fi
          deadline=$(( started + HOP_BUDGET_SECONDS ))
          hold_until=$(date -d "$(date +%F) ${SESSION_TAIL_CLOSE:0:2}:${SESSION_TAIL_CLOSE:2:2}:00" +%s)
          if [ "$deadline" -lt "$hold_until" ]; then
              hold_until=$deadline
          fi
          scripts/intraday-closed-hold.sh "$hold_until"
```

- 這一步不需要任何 secret，因為 `market-day` 只打證交所日曆與 MIS。
- 時間預算：最多留到 `hop-started-at + HOP_BUDGET_SECONDS`（5 小時 30 分）。job 的 `timeout-minutes: 350` 還剩 20 分鐘給後面的步驟。
- 「保底停留」不用改。留過之後這一棒的時間已遠超過 180 秒，不會再補睡。
- 下列都不改：「等到開盤」的 `in_session`、`in_tail`、`next_open`，以及 `market-calendar.json`。
