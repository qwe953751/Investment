# 台股操作表雙向同步實作規格

## 目的與權威來源

- Google Sheet「操作(台)」是人工編輯主檔，保存 Buy、Stock、48 個族群與既有 D 欄公式；目前受控範圍是第 3 列標題下的 B:AZ。
- Supabase 是網站讀取、版本控制、草稿與對帳鏡像，不是另一份可獨立漂移的清單。
- 網站不把 Google service account 私鑰或 Supabase service role key 放進瀏覽器。
- `Buy`、`Stock`、48 個族群 checkbox 與資料列順序可編輯／取代；D 欄「營收創高」由既有試算表公式自動產生，不是同步寫入資料。
- 網頁顯示受控欄位共 52 欄（權重、Buy、Stock、D 欄唯讀結果、48 族群）；刪除按鈕只在編輯時放於 Stock 儲存格，不得新增「操作」資料欄。舊 `column_order` 的 `actions` 鍵會忽略並清除。
- 第 1、2 列統計公式、第 3 列標題、A 欄計算值、D 欄公式／格式、checkbox 驗證、凍結列與其他分頁都不在受控寫入範圍。

## 資料流

```text
Google Sheet B:C、E:AZ --import--> Edge Function --RPC--> Supabase active snapshot / rows
網站編輯 --save-draft--> Edge Function --RPC--> Supabase pending snapshot
網站匯出 --export--> Google hash 檢查 --batchUpdate B:C、E:AZ + deleteDimension 尾端多餘列--> 讀回驗證 --RPC--> Supabase active
```

匯出是完整取代受控資料列，不是逐列 patch：網站刪除 2 筆後，Google Sheet 尾端多出的 2 個標的列會以 `deleteDimension` 實體整列刪除，兩邊標的數量相同；
網站刪到 0 筆時，保留第 4 列作為空白輸入模板，只清除該列 B:C、E:AZ，並刪除後續舊標的列。一般匯出不會刪除原本就空白的預留列。
整列刪除只作用於操作分頁的尾端，先確認 AZ 以外沒有值／公式／驗證／註記、也沒有跨越待刪列的合併儲存格；刪除後回讀驗證標的 hash／筆數、表頭、統計公式、保留列 A／D 欄與凍結列。
匯出會用隱藏 developer metadata 記錄已整理的快照 ID，避免重試時重複刪除空白列。若舊版已先清空標的值但留有殘列，受保護的 `repair-stale-tail` 會在狀態 clean、沒有 pending 草稿、目前 hash 相符，且快照歷史明確證明最近一次匯出少了標的時才修復一次。
若 Google Sheet 自上次匯入後已被人工修改，hash 不相同時回傳 HTTP 409，禁止覆蓋，使用者必須重新匯入。

## Google Sheet 欄位契約

- `Buy`：B 欄；整數且不可小於 0。
- `Stock`：C 欄；格式為「代號 空白 名稱」，代號不可重複。
- `營收創高`：D 欄由原有公式自動產生。同步不把 D 欄匯入、納入 hash 或寫回；網站顯示另以 `revenue_latest` 衍生，兩者不互相覆寫。
- 族群：E:AZ 共 48 欄。每欄以 developer metadata `metadataKey=invest.asset-operation`、`metadataValue=group:<uuid>` 識別，不能只用標題文字（目前有重複的「導線架」）。
- `A` 欄與第 1、2 列不寫入；只更新 B:C、E:AZ 的 `userEnteredValue`，刻意跳過 D，保留公式、格式、checkbox 驗證與凍結列。新增資料列先以 `copyPaste PASTE_NORMAL` 從第 4 列複製版型，讓 D 欄公式跟著延伸。

## Supabase schema／權限

- `db/058_asset_operation_full_sheet_sync.sql`
  - 擴充 `asset_operation_rows`：`stock_code`、`stock_name`、`group_flags`、`snapshot_id`。
  - 新增 `asset_operation_group_columns`、`asset_operation_snapshots`、`asset_operation_sync_state`。
  - 建立 `replace_asset_operation_snapshot(...)`，以版本號與 transaction 一次取代 active rows。
- `db/059_asset_operation_sync_write_hardening.sql`
  - authenticated 只保留操作表、設定表的 SELECT；INSERT／UPDATE／DELETE 只能由 Edge Function 的 service role／RPC 執行。
- `db/060_asset_operation_sync_cron.sql`
  - UTC 10:30（台北 18:30）呼叫 import；有 dirty 草稿時不覆蓋。
  - 依賴 Vault secret `asset_operation_cron_secret`；未設定時 migration 會略過建立 job。

## Edge Function actions

檔案：`supabase/functions/asset-operation-sync/index.js`

- `bootstrap-metadata`：第一次使用時建立 Buy／Stock／D 與 48 個族群 metadata。正常 `import` 在 metadata 完全不存在時會自動 bootstrap；已有部分 metadata 時停止並要求修復，避免產生重複識別碼。
- `repair-metadata`：只刪除同一欄位的重複同步 metadata，並重新確認 Buy／Stock／D 與 48 個族群都完整。
- `import`：讀 metadata、只從 Sheet 讀 B:C 與 E:AZ，驗證列與 checkbox，建立 active snapshot。有 pending 草稿時回 HTTP 409／`code=draft_pending`；只有管理者 JWT 且 body 帶 `overwriteDraft:true`（網站確認視窗按「確定」）才會以 Google 為準匯入，並把 pending 草稿標為 `superseded`（保留紀錄）。cron 身分永不覆蓋草稿。
- `save-draft`：接收網站目前完整列集合，建立 pending snapshot；`expectedVersion` 不符回 409。
- `export`：讀最新 pending snapshot，檢查 base hash，在單一批次寫 B:C、E:AZ 並實體刪除多出的尾端標的列，重新讀取並驗證列數、資料 hash、統計公式、標題、保留列 A／D 與凍結列後才 active；D 欄完全不寫入。
- `repair-stale-tail`：只接受 cron secret；僅依最近 `google_import`／`google_export` 快照差額、clean 狀態、無 pending 草稿與 Google hash 相符判斷舊版殘列，並以 Sheet metadata 防止重複修復。
- `save-column-order`：只保存目前 52 個顯示欄位的順序；`actions` 是舊版 UI 專用鍵，不再接受或寫回 `asset_operation_settings`。
- `status`：讀取同步狀態供網站顯示。

## 失敗與復原

- HTTP 409：Google 或網站版本衝突；不要重試 export，先 import 並確認差異。
- Google 寫入後驗證失敗，或匯出回 409：Google 是主檔，在網站按「從 Google Sheet 匯入」並確認覆蓋，即可作廢草稿、以 Google 為準重新對帳；不需手動改資料庫。
- 新增列的 A／D 欄驗證只檢查有套上第 4 列公式；寫入前就存在的保留列仍不得改動（`writeGoogle` 回傳 `appendedFromRow` 作分界）。
- Edge／Google secrets 未設定：前端只顯示錯誤，不退回直接 REST 寫入。
- migration 尚未套用：不可發布會查詢新表的正式前端；先完成 schema／function 部署。
- 雙向同步不涉及下單、投資建議或買賣訊號；任何擴充都必須另訂 schema 與權限審查。
