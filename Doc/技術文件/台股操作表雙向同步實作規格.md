# 台股操作表雙向同步實作規格

## 目的與權威來源

- Google Sheet「操作(台)」保存人工編輯的 Buy、Stock 與 48 個族群；目前受控範圍是第 3 列標題下的 B:AZ。
- 網站的 `revenue_latest` 是「營收創高」唯一權威；Google Sheet D 欄是網站結果的投影，不能反向覆蓋網站。
- Supabase 保存網站讀取、版本控制、草稿與對帳快照。
- 網站不把 Google service account 私鑰或 Supabase service role key 放進瀏覽器。
- `Buy`、`Stock`、48 個族群 checkbox 與資料列順序可編輯／取代；D 欄只寫入網站計算出的值，不讀取既有公式結果。
- 第 1、2 列統計公式、第 3 列標題、A 欄計算值、D 欄格式、checkbox 驗證、凍結列與其他分頁不受格式寫入影響。

## 資料流

```text
Google Sheet B:C、E:AZ --import--> Edge Function --RPC--> Supabase active snapshot / rows
網站 revenue_latest（台北上個月）--> 操作表唯讀營收創高欄
網站編輯 --save-draft--> Edge Function --RPC--> Supabase pending snapshot
網站匯出 --export--> Google hash 檢查 --batchUpdate B:C、D、E:AZ--> 讀回驗證 --RPC--> Supabase active
月營收 workflow（明確啟用）--> refresh-revenue-high --> Google Sheet D 欄
```

匯出是完整取代受控資料列，不是逐列 patch：網站刪除 2 筆後，Google Sheet 受控列也會清除多出的 2 筆，兩邊數量相同；
若網站刪到 0 筆，前端會再次確認後清空受控資料列；D 欄投影也會清除舊值，格式與驗證保留。
若 Google Sheet 自上次匯入後已被人工修改，hash 不相同時回傳 HTTP 409，禁止覆蓋，使用者必須重新匯入。

## Google Sheet 欄位契約

- `Buy`：B 欄；整數且不可小於 0。
- `Stock`：C 欄；格式為「代號 空白 名稱」，代號不可重複。
- `營收創高`：D 欄唯讀投影。網站只採用台北時間上個月的 `revenue_latest`；`high_months >= 13` 寫入 checkbox `TRUE`，缺少當月資料或未達門檻寫入 `X`。Sheet 舊 D 公式／值不會匯入網站，也不參與 hash。
- 族群：E:AZ 共 48 欄。每欄以 developer metadata `metadataKey=invest.asset-operation`、`metadataValue=group:<uuid>` 識別，不能只用標題文字（目前有重複的「導線架」）。
- `A` 欄與第 1、2 列不寫入；只更新 B:C、D、E:AZ 的 `userEnteredValue`，保留格式、checkbox 驗證與凍結列。新增資料列先以 `copyPaste PASTE_NORMAL` 從第 4 列複製版型，再用網站營收值覆蓋 D 公式。

## Supabase schema／權限

- `db/058_asset_operation_full_sheet_sync.sql`
  - 擴充 `asset_operation_rows`：`stock_code`、`stock_name`、`group_flags`、`snapshot_id`。
  - 新增 `asset_operation_group_columns`、`asset_operation_snapshots`、`asset_operation_sync_state`。
  - 建立 `replace_asset_operation_snapshot(...)`，以版本號與 transaction 一次取代 active rows。
- `db/059_asset_operation_sync_write_hardening.sql`
  - authenticated 只保留操作表、設定表的 SELECT；INSERT／UPDATE／DELETE 只能由 Edge Function 的 service role／RPC 執行。
- `db/060_asset_operation_sync_cron.sql`
  - UTC 10:30（台北 18:30）呼叫 import；有 dirty 草稿時不覆蓋。
  - 依賴 Vault secret `asset_operation_cron_secret`；未設定時 migration 會略過建立 job。

## Edge Function actions

檔案：`supabase/functions/asset-operation-sync/index.js`

- `bootstrap-metadata`：第一次使用時建立 Buy／Stock／D 與 48 個族群 metadata；若已有 metadata 會停止，避免產生重複識別碼。
- `import`：讀 metadata、只從 Sheet 讀 B:C 與 E:AZ，驗證列與 checkbox，建立 active snapshot；dirty 草稿時拒絕。若寫入已啟用，會嘗試用網站當月營收值重寫及讀回驗證 D；D 投影失敗會在成功匯入結果中附警告，不改變網站使用自身營收資料的原則。
- `save-draft`：接收網站目前完整列集合，建立 pending snapshot；`expectedVersion` 不符回 409。
- `export`：讀最新 pending snapshot，檢查 base hash，取一份網站有效月份營收快照，在單一批次寫 B:C、D、E:AZ，重新讀取並驗證資料列／族群／D 投影後才 active。
- `refresh-revenue-high`：只允許管理者 JWT 或 cron secret；不需帳戶 ID，只更新並驗證 D 欄。供月營收 workflow 在明確啟用後呼叫。
- `save-column-order`：欄位順序經 Edge Function 寫入 `asset_operation_settings`。
- `status`：讀取同步狀態供網站顯示。

## 必要 secrets 與首次部署

Edge Function secrets（值不可寫入 repo、文件、log）：

```text
GOOGLE_SHEETS_CLIENT_EMAIL
GOOGLE_SHEETS_PRIVATE_KEY
ASSET_OPERATION_SPREADSHEET_ID
ASSET_OPERATION_SHEET_ID=58931507
ASSET_OPERATION_SHEET_NAME=操作(台)
ASSET_OPERATION_CRON_SECRET
ASSET_OPERATION_WRITE_ENABLED=true
```

目前部署狀態（2026-09-23 修改前）：`058`、`059`、`060` 已套用正式 Supabase；受控 Supabase 清單顯示 `asset-operation-sync` v14 ACTIVE。唯讀 SQL 已確認 Vault 有 `asset_operation_cron_secret`，但未讀取其值；這不代表 GitHub Actions secret／variable 或排程 job 已完成設定。

第一次部署順序：

1. 以有 DDL 權限的 Management API／SQL editor 套用 `058`、`059`、`060`。
2. 將 Google Sheet 分享給 service account，權限至少 Editor。
3. 部署 `asset-operation-sync`，設定上述 secrets。
4. 呼叫 `bootstrap-metadata`（只允許 admin／cron），再執行 `import`。
5. 做 smoke test：網站新增 1 筆、刪除 1 筆、改一個族群、儲存草稿、匯出；確認 Google Sheet 受控列數、D 欄網站投影、兩個同名族群與 A 欄公式／格式均正確。
6. 如需月營收更新後即時同步 D，於 repository Actions 設定 variable `ASSET_OPERATION_REVENUE_SYNC_ENABLED=true`，並設定 secret `ASSET_OPERATION_CRON_SECRET`（必須與 Supabase Edge／Vault 既有值相同）；未設定時 workflow 預設略過投影。

## 失敗與復原

- HTTP 409：Google 或網站版本衝突；不要重試 export，先 import 並確認差異。
- Google 寫入後驗證失敗：不要再次匯出；保留 pending snapshot，查 Google 實際 B:AZ 與 D 投影後人工對帳。
- 匯入成功但回報 D 投影失敗：網站仍使用網站營收；檢查 Edge 寫入旗標、service account 的 Sheet 權限／D 欄保護，再單獨呼叫 `refresh-revenue-high`。
- Edge／Google secrets 未設定：前端只顯示錯誤，不退回直接 REST 寫入。
- migration 尚未套用：不可發布會查詢新表的正式前端；先完成 schema／function 部署。
- 雙向同步不涉及下單、投資建議或買賣訊號；任何擴充都必須另訂 schema 與權限審查。
