# 熱門族群泡泡圖：整理記錄、設計理念與結論

## 1. 本次調整記錄

本文件統合熱門族群泡泡圖的指標定義、正式排版、互動方式與設計取捨。2026-08-29 定義價格反應與廣度修正，2026-10-09 筆記 #78 定案自適應線性軸、大泡泡與等高排序排行；2026-10-10 將兩輪內容按原有章節整理，沒有變更公式或網站行為。

公式中的「調整成 20%」是指：

- 價格反應是主要訊號，保留 80% 的主導性。
- 族群廣度只作最多 20% 的可信度修正。
- 這個 80%／20% **只用在泡泡圖 Y 軸**，沒有改動排行榜「市場熱度」既有的資金熱度 60%／族群廣度 25% 權重。

原本把族群廣度直接放在 Y 軸，會把「有多少成員一起動」誤當成價格結果；本輪改成以成交值加權漲跌幅作 Y 軸，再讓廣度調整訊號可信度。

資料流保持單一計算來源：

`TopicHeatCalculator` → `TopicHeatRow` → `StaticSiteExporter` → `topics.json` → `site.js` 泡泡圖

沒有新增資料庫欄位，也沒有讓前端自行重算公式。

## 2. 指標定義

### 2.1 成交值加權價格反應 `P`

對族群內每一檔有有效成交值與漲跌幅的成員：

```text
P = Σ(Vᵢ × rᵢ) ÷ Σ(Vᵢ)
```

其中：

- `Vᵢ`：該檔股票在本期全市場成交比，作為成交活動權重。
- `rᵢ`：該檔股票本期漲跌幅。
- 沒有報價或成交比不大於 0 的成員不放進這個加權分子與分母。

這個結果回答的是：「這個族群的交易活動最後反映出多少價格漲跌？」它不是法人淨買賣、主動買賣差，也不是可以直接宣稱為『金流進出』的資料。

### 2.2 族群廣度比例 `B`

既有族群廣度分數為 0～100，本圖將它轉成比例：

```text
B = clamp(族群廣度 ÷ 100, 0, 1)
```

廣度本身仍由既有 C# 公式計算，包含排行參與率、上漲家數比、成交分散度與實際有量成員折減。

### 2.3 泡泡圖 Y 軸 `Y`

```text
Y = P × (0.80 + 0.20 × B)
```

因此：

- 廣度為 0 時，保留 `P` 的 80%。
- 廣度為 100 時，保留 `P` 的 100%。
- 廣度只能調整價格反應的可信度，不會把正負方向翻轉，也不會和百分比直接相加。

例如 `P = +5%`、`B = 50%` 時：

```text
Y = 5% × (0.80 + 0.20 × 0.50) = +4.50%
```

## 3. 泡泡圖畫面設計

正式畫面採「泡泡圖＋右側排行＋下方成員表」。原有觀察期間、排行範圍與列表／泡泡圖切換保留，預設仍為列表。以下規格以目前 `site.js`／`site.css` 實作為準，發布證據集中在第 7 節。

| 視覺元素 | 使用欄位 | 意義 |
|---|---|---|
| X 軸 | `fundScore` | 原成交活動熱度分數（0～100），座標上限隨目前圖中資料調整；不是淨金流 |
| Y 軸 | `breadthAdjustedPriceReactionRate` | 成交值加權價格反應，經族群廣度最多 20% 修正 |
| 泡泡面積 | `fundRawShare` | 與圖中族群的累計成交活動成比例；半徑取相對成交活動的平方根 |
| 泡泡顏色 | `breadthScore` | 廣度 ≥ 60 為廣、≤ 40 為窄，其餘為中性／資料不足 |
| 圓內文字 | 族群名稱、Y 軸值 | 常駐顯示名稱與價格反應百分比；名稱超過 8 字元顯示前 7 字元加省略號 |
| 圖與右側排行集合 | `compositeScore` | 目前範圍內有有效 X／Y 值的市場熱度前 20 名；不足 20 名就顯示實際數量 |

**自適應線性座標**

X 軸下限固定 0，上限依圖中最大原分數加 2 後向上取整至 10 的倍數，限制為 10～100。例如最高 35.3 分，軸顯示 0～40；最高 100 分，仍顯示 0～100。Y 軸以 0 為中心對稱，上下界取圖中最大價格反應絕對值、向上取整至 1 個百分點，至少 ±3%。寬圖顯示 5 個 X 軸刻度，窄圖顯示 3 個；Y 軸均顯示上界、半上界、0、半下界與下界，0 軸加深。

只縮放座標範圍，X／Y 數值直接使用 C# 輸出，不在前端重新正規化分數。同分或相近族群仍使用原座標。

**排版與尺寸**

| 項目 | 正式規格 |
|---|---|
| 寬圖 | 圖表容器寬度 ≥ 600px：高度 680px、最大泡泡半徑 64px |
| 窄圖 | 圖表容器寬度 < 600px：高度 460px、最大泡泡半徑 40px |
| 桌面左右欄 | 圖表占剩餘寬度，排行寬 340px；視窗 ≤ 1000px 時排行寬 290px |
| 手機／窄視窗 | 視窗 ≤ 800px 時改為圖表、排行、成員表由上至下排列 |
| 等高與捲動 | 排行總高度跟隨圖表的 680px／460px；超長表格在區內使用原生垂直捲軸，可拖曳或捲動 |
| 固定資訊 | 排行標題與市場熱度排序鈕位於捲動區外，表格欄位表頭固定在捲動區上緣 |
| 成員明細 | 跨左右兩欄顯示；內容區最高 480px，表格最小寬度 850px，超出時在明細容器內捲動 |

圖表尺寸依**圖表容器寬度**判斷，左右／上下排列依**視窗寬度**判斷，兩者不是同一個斷點。泡泡依相對成交活動決定大小，大泡泡先畫、小泡泡後畫；文字使用輪廓提高辨識度，圖表邊界保留泡泡半徑所需空間。視覺圓半徑不設最小值，但透明點擊區半徑至少 22px。

**排行、選取與成員表**

右側欄位為名次、族群、活動熱度與價格反應。預設依市場熱度由高到低；市場熱度按鈕及族群／活動熱度／價格反應表頭均可雙向排序。排序只改同一組族群的列順序與編號，不替換泡泡集合或改變圖軸。族群完整名稱與原活動熱度分數保留在排行中。

| 操作 | 畫面結果 |
|---|---|
| 第一次點泡泡或排行族群名稱 | 同步標記圓與排行列，將選取圓畫在最上層，淡化其餘泡泡；下方展開既有成員表 |
| 點其他族群 | 改為選取該族群，成員篩選回到全部、排序回到市場成交比由大到小 |
| 再點同一族群，或按明細「收合」 | 取消標記、還原所有泡泡與原繪製層次，收合成員表 |
| 點泡泡後、排行排序後、圖表寬度改變後 | 檢查選取列是否可見；需要時只捲排行容器，扣除固定表頭高度，讓該列進入可見區 |
| 選取列已完整可見 | 保持排行捲動位置；定位不捲整頁、不轉移焦點 |
| 切換期間／範圍或重新載入 | 清除此次圖表選取 |
| Enter／Space 操作泡泡 | 與點擊相同；容器寬度重繪保留泡泡焦點 |

成員表沿用原網站的全部／直接／繼承／近期有成交篩選、市場成交比與漲跌幅排序、K 線及營收元件，沒有建立第二套成員資料或計算邏輯。

正式畫面不加入樣本切換器、尺寸滑桿、放大按鈕、額外說明卡或外置引線標籤；選取還原由同一族群第二次點選完成，不要求使用者另找清除操作。舊快照缺必要欄位時提示更新，不補造資料。

## 4. 設計理念與取捨

排版優化以「先看族群分布，再定位族群，最後查看成員」為閱讀順序，對應第 3 節的正式規格。以下是本次設計決策的理由與代價，並非新增待實作功能。

| 決策 | 理由 | 取捨與未採方案 |
|---|---|---|
| 自適應線性軸 | 題材分數集中在低分區時，利用圖表寬度展開差異，同時保留原分數及線性距離 | 固定 0～100 較便於跨範圍比較，但低分族群會擠在左側；根號軸改變距離意義，名次軸失去分差，再把範圍最高分改成 100 會改變原分數的讀法，因此未採用 |
| 名稱與百分比常駐圓內 | 讓使用者直接辨識族群與價格反應，減少來回對照排行的負擔 | 空白泡泡必須靠提示或列表才能讀懂；外置標籤與引線另占空間，因此未採用。常駐文字仍可能重疊，選取凸顯與完整名稱排行提供查閱途徑 |
| 大圖搭配相對面積 | 增加閱讀空間；用面積而非半徑對應成交活動，避免把大小差異平方放大 | 最大半徑限制為 64px／40px；小族群可能無法把全部文字包在圓內，不為了包住文字放大其成交活動面積 |
| 圖與排行等高、列表區內捲動 | 形成共同閱讀區域，避免長排行拉出圖下方大片空白；固定表頭保留欄位上下文 | 使用原生捲軸而非自製拖曳元件；手機上下排列，維持觸控與窄版可讀性 |
| 圖與排行同步、自動定位 | 使用者點到族群即可看到其排行列與原分數，無需手動尋找 | 只捲排行容器；不使用可能連整頁一起移動的 scrollIntoView，也不另加跳轉按鈕 |
| 再次點選即可還原 | 同一位置完成選取與取消，減少操作路徑；選取時保留整體分布作背景 | 單次只選一個族群；取消後恢復層次與明細狀態，不延伸為多選比較或資料快取清除 |
| 成員表放在圖下方、沿用既有元件 | 保留圖與排行作比較背景，又有足夠寬度顯示成員欄位，維持一致資料來源 | 不採額外側邊抽屜或第二套明細頁；手機以明細容器橫向捲動容納既有欄位 |

### 4.1 為什麼 Y 軸不用族群廣度

族群廣度是「參與面」；它能說明上漲或下跌是否由多數成員共同發生，卻不是資金活動造成的價格結果。把它直接當 Y 軸，會讓一個成交很少但多數小型成員微幅上漲的族群，看起來和真正有大量成交、價格明顯反應的族群同等重要。

現在由 `P` 主導 Y 軸，廣度只負責回答「這個價格反應有多廣、可信度要不要打折」，單位仍是百分比，圖軸不會混合分數與報酬率。

### 4.2 為什麼不能把成交熱度叫成金流

成交比只有「交易量／成交值的相對大小」，沒有買方與賣方的方向。每一筆成交同時有買方和賣方；只靠 OHLCV 無法判斷是法人買進、散戶追價、主動買單成交，還是持有人逢高賣出。

所以畫面使用「資金熱度」或「成交活動熱度」；右上角可以描述成「高活動＋正價格反應」，右下角可以標記為「高活動但價格走弱」，但不能直接標示「資金流入」或「資金撤出」。

若要實現真正的方向性金流，必須先定義方向與來源，例如：

- 三大法人或特定交易者的淨買賣金額。
- 主動買成交額 − 主動賣成交額。
- 委買／委賣深度與撤單資料。

這些資料需要交易所或明確的即時資料源，不能由目前的日 K 與成交值推導出來。

### 4.3 如何閱讀四種位置

- 右上：成交活動高、價格反應正；若顏色也偏廣，表示較多成員共同參與。
- 右下：成交活動高、價格反應負；表示成交活躍但價格走弱，不能由此推斷資金撤出或買賣方向。
- 左上：價格反應正，但目前成交活動較低；可能是早期反應、流動性不足或少數股票推動。
- 左下：成交活動較低、價格反應負；描述當期分布，不據此判斷後續走勢。

左右位置應配合當下軸刻度閱讀，切換範圍後不能只憑畫面位置比較熱度。泡泡大小只代表圖中族群的相對成交活動，不代表報酬率、信心或投資建議。

## 5. 驗證與限制

- 排版與互動已完成本機及正式瀏覽器驗證：等高、圓內文字、自動定位、雙向排序、成員展開與再次點選還原；窄版無整頁水平溢出。測試數與發布證據見第 7 節。
- C# 測試固定檢查 `P`、廣度分數與 `Y = P × (0.80 + 0.20 × B)` 的結果，避免前端公式漂移。
- 靜態資產測試固定檢查新欄位、Y 軸說明與廣度顏色分類仍存在。
- 盤中資料沿用現有快照更新鏈；快照成功更新後，泡泡圖會使用同一份最新族群資料。更新頻率由盤中收集器與頁面刷新機制決定，本圖本身不另開請求。
- 自適應軸與泡泡面積均依目前圖中集合顯示；跨期間／範圍比較必須看原分數與刻度，不能僅比較位置或圓大小。
- 不做碰撞位移或自動拆開同分點，避免改變數據位置。密集區的圓與文字仍可能互相遮擋；選取可置頂辨識，排行提供完整名稱。
- 所有標籤都有繪製，不代表所有文字同時無遮擋；名稱截斷只影響圓內文字，完整名稱仍在排行、泡泡標題與無障礙名稱。
- 右側只列圖中前 20 名，完整族群需切回列表；圖中有效族群的前 20 名可能與包含無效 X／Y 值的完整列表不同。
- `Y` 是價格反應代理指標，不是預測模型，也不處理下單、買賣訊號或投資建議。
- 成交比在多個族群重複計入是刻意行為：本圖問的是每個族群的活動熱度，不把一檔股票的成交活動切割給不同族群。

## 6. 結論

正式設計採用「成交值加權價格反應為主、族群廣度為輔」，以自適應線性軸呈現：

```text
X = 資金／成交活動熱度
Y = 成交值加權漲跌幅 × (80% + 20% × 族群廣度比例)
面積 = 圖中族群相對成交活動
顏色 = 族群廣度
內容 = 圓內名稱與價格反應百分比
排版 = 泡泡圖＋等高可排序排行＋下方成員表
操作 = 選取同步定位，再點同一族群還原
```

這樣既保留使用者想觀察的成交活動，又不把成交活動誤稱為有方向的金流；廣度負責降低「單一股票拉動」造成的誤讀。未來若取得有方向的金流原始資料，再另設金流軸或切換指標，不覆寫本代理指標的歷史意義。
