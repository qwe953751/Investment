## 0. 使用者已定案的決策（不要再改）

1. **資產頁台股資料一律使用自訂頁籤（個股＋ETF 兩個分頁）同一份資料。**
   - 開盤後（09:00 起）用盤中資料。
   - 收盤後**不能**直接切盤後：繼續用當天最後一輪盤中，**等當天官方盤後資料上線後**才切成盤後。

   - 不設任何門檻（例如 ±40% 之類的猜測規則一律禁止），只用交易所官方參考價自動換算。
   - 除息、除權、減資、面額變更、ETF 分割／反分割全部適用。
3. **今年才掛牌的標的**：年漲跌改算「掛牌以來」（以官方掛牌參考價為起點）。
4. **興櫃盤中收集延長到 15:00**（興櫃交易到 15:00；上市櫃仍 13:30 收盤）。

## 3. 目標設計

### 3.1 還原方式：向前還原（不可改成向後還原）

- 今天（盤中現價、今天收盤）維持真實成交價；**過去**的價格乘上「之後所有事件倍數的連乘」換算到今天的基準。
- 向後還原會讓現價變成市場上不存在的數字，市值、損益、券商對帳全錯，禁止採用。
- **每個交易日的輸出以「當天」為基準（as-of）**：之後才發生的事件不會改變那天已算出的漲跌幅（漲跌幅對整段縮放不變）。只有 K 線圖的歷史絕對價位會隨新事件整段縮放，這是還原圖的正常行為。

### 3.2 官方參考價規則（每檔、每個有收盤的交易日 D）

| 市場 | 條件 | 參考價 ref(D) |
|---|---|---|
| 上市（含 ETF、TDR） | `漲跌(+/-)` 為 +／−／空白 | `收盤 − 符號 × 漲跌價差`（F2） |
| 上市 | `漲跌(+/-)` 為 `X` | 當日 TWT49U 的「除權息參考價」 |
| 上櫃（含 ETF） | `漲跌` 為數字 | `收盤 − 漲跌`（F3、F5） |
| 上櫃 | `漲跌` 為文字（除息／除權／除權息） | 前一交易日的 `次日 參考價`（F4），並與 exDailyQ P1 交叉核對 |
| 興櫃 | 有日均價 | `前日均價`（F7；除權息日語意待驗證，見 §9） |
| 任一市場 | 該證券第一個交易日 | 記為「掛牌參考價」（上市櫃：`收盤 − 漲跌`；興櫃：前日均價若有） |

- 倍數：`factor(D) = ref(D) ÷ close(P)`，P 是同一證券 D 之前**最近一個有收盤**的交易日。沒有事件時剛好等於 1，不需要任何門檻。
- 停牌、無成交日不用特別處理：參考價會沿用，第一個有成交日的 `收盤 − 漲跌` 自然帶出恢復參考價。
- **換板例外**：若 P 與 D 的市場不同（興櫃 → 上市櫃轉板、上櫃 → 上市），factor 一律為 1，不視為權益事件，寫入日誌。轉板首日的「日漲跌」仍以官方參考價（承銷價）為準。
- 興櫃的 close 是日均價，factor 用 `前日均價 ÷ 前一交易日日均價`。

### 3.3 資料落地（`data` branch 的 `imports/`，只增不減）

- 沿用既有「每個資料族群一個獨立版本號＋專屬補抓指令」模式（`DailyQuoteSnapshot` 的 `EtfSchemaVersion`、`EmergingSchemaVersion`、`TdrSchemaVersion` 與 `backfill-etfs`、`backfill-emerging`、`backfill-tdr`）。
- 新增 `ReferenceSchemaVersion`（從 1 開始）與 `backfill-reference` 指令：
  - `DailyQuote` 新增原始官方欄位（可為 null）：`ChangeSign`／`Change`（上市）、`ChangeText`（上櫃文字漲跌）、`NextReferencePrice`（上櫃次日參考價）、`PreviousAveragePrice`（興櫃前日均價，未夾值的原始數字）、`ReferencePrice`（由 §3.2 決定的當日官方參考價，回補時算好存入）。
  - 快照新增 `CorporateActions`（當日 TWT49U／exDailyQ／ETF 分割表原始列：代號、P0、P1、類別、來源），所有證券種類都收，不再用 `IsCommonStockTicker` 過濾。
  - 每日回補時順手解析（MI_INDEX、dailyQuotes、des010 本來就有下載，**不增加每日請求**）；X 日的 TWT49U 用既有 `CorporateActionClient` 的月份區段查詢。
  - **舊快取補欄位**：`backfill-reference` 重抓缺欄位的日期，先比對重抓回來的收盤價與既有快取逐檔相同才合併新欄位，不同就停止並警報，絕不覆寫既有欄位、絕不刪日期。
  - 證交所會封鎖密集請求：每次請求間隔 ≥ 6 秒、失敗退避、單次執行設上限天數（建議 40 天），可跨數次 workflow 接續完成 300 個交易日。
- **匯出改為離線決定性計算**：`TradingValueRankingQueryService.LoadAsync` 不再線上呼叫 `CorporateActionClient.GetAsync`，改由快取欄位計算倍數表。

### 3.8 前端（site.js）

**資產頁報價來源與切換規則（P1、P2）**

- 盤中：改用 `ensureIntradaySnapshot()`／`intradayRaw` 同一份 CDN 快照（與自訂頁共用快取與分頁廣播），刪除 `fetchAssetIntradayQuotes` 的 REST 查詢。
- 盤後：改讀自訂頁同一天的盤後資料（`1-{date}.json` 的個股與興櫃、`tdr/{date}.json`、`etf/{date}.json`）。為了手機載入，匯出時由**同一批列物件**另存精簡檔 `data/quotes/{date}.json`（代號、市場、種類、收盤、日／週／年漲跌與基準類別、交易日），數字保證一致。
- 每一檔各自判斷，看資料日期不看時鐘：
  - 盤中候選只採 `session_phase` 不是 `preopen` 的輪次（09:00 以後）。
  - **盤後資料日期 ≥ 盤中資料日期 → 用盤後；否則用盤中。**
  - 結果：開盤前與休市日顯示最近盤後；09:00 後盤中；收盤後到當天盤後上線前顯示「盤中最後一輪（時間）・官方收盤未公布」；上線後自動切盤後。當天盤後整晚沒進來時，隔天開盤前仍顯示前一天最後一輪盤中，不會退回更舊資料。
  - 興櫃 13:35–15:00 跟著尾段輪次更新，標示興櫃自己的資料時間。
- 持倉漲跌、K 線即時棒都跟同一個選擇；`assetIntradayLiveKLine` 改用同一套判斷。

**每日資產快照定稿（P3）**

- 當天快照在以下時機覆寫：盤中第一次（暫定）、收盤後最後一輪（暫定）、**當天盤後上線後第一次重讀（定稿）**。
- 判斷是否已定稿不需要 DDL：`row.updated_at ≥ 本版 manifest.generatedAt（台北時間）` 且 `manifest.latestTradingDate` 是今天，且台股持倉全部已是今天盤後資料。
- 限制寫進文件：當晚沒有任何裝置打開資產頁就無法定稿。要做到完全不漏需伺服器端補算（牽涉 RLS 與公式重複），本次不做，列入 TODO。

**其他**

- 台股代號規則統一成一個函式，與 C# `TaiwanSecurityRules`／`QuoteFieldParser` 一致：`^(?:\d{4}|\d{4}[A-Z]|\d{5}[A-Z]|\d{6})$`（普通股、特別股、ETF 字尾、六碼 ETF／TDR），替換 P4 各處。C# OCR Worker 的 `NormalizeTicker` 本來就接受英數字，**不需要重建 OCR Worker**。
- K 線即時棒（P7）：前一收盤改用快照的 `reference_price`；歷史 K 棒乘上快照提供的 `adjustment_factor` 再畫。倍數由 C# 算，前端只負責乘。
- 年漲跌欄顯示「掛牌以來」時要有明確標示，週漲跌同理。
- 量柱：成交股數沒有任何指標使用（量比等都用成交金額），只有 K 線量柱。二選一，**動版面前先做樣板給使用者挑**：
  - A：量柱改顯示成交金額（與指數 K 線一致，天生不受分割與配股影響）。
  - B：保留股數，只在分割、反分割、面額變更、減資、配股事件依官方股數比例換算；比例不可用價格倍數推算。

### 3.9 防錯與警報（不猜、不默默略過）

- 上市每一個 `X` 日都必須在 TWT49U 找到該檔；上櫃每一個文字漲跌日都必須有前一日次日參考價且與 exDailyQ P1 相符；ETF 分割日要與證交所 ETF 分割表相符。
- 盤中記錄的 MIS `y` 與盤後算出的 ref(D) 逐檔比對（四捨五入到交易單位後必須相等）。
- 任一項不符或缺資料：該檔受影響的漲跌與 K 線顯示「—」並寫入網站警報（沿用 `alert` 指令）；**不讓整站停更**，也不輸出猜測值。
- 盤中最後一輪與當天盤後，若價格相同，日／週／年漲跌必須完全相同；不同則警報。
