# 美股成交金額前 20：免費資料源與公開展示評估

> 調查日期：2026-09-15  
> 文件性質：方案評估，尚未代表採用或完成實作  
> 範圍：取代 Massive 的美股盤後成交排行來源；日股／韓股 KIS 資料流不在本次替換範圍

## 1. 結論

目前沒有找到一個可以同時滿足以下全部條件的 API：

1. 免費；
2. 提供美股全市場盤後資料；
3. 能正確產出「成交金額前 20」，而不是成交量或交易筆數前 20；
4. 允許把結果寫入公開 `data` branch、公開 CDN 或網站，提供帳號持有人以外的人查看；
5. 條款明確允許上述公開展示或再散布。

Alpha Vantage、Alpaca 與 Twelve Data 都能提供部分相近功能，但不是完整替代品，且沒有
消除公開展示／再散布限制。現階段條款路徑最清楚的免費方案是 **TradingView 官方 Widget**，
因為它本來就是供網站嵌入使用；但它不是行情 API，不能輸出目前自訂的前 20 JSON 與雙欄排行。

因此需要在以下兩項之間選擇：

- **保留精確、自訂的成交金額前 20：**取得資料供應商書面公開展示授權，或改用包含再散布權的付費方案。
- **維持免費並公開給親友使用：**把美股區塊改為 TradingView 成交金額熱度圖，接受延遲資料及不同版型。

## 2. 本案需求與判定標準

### 2.1 功能需求

- 美股只需要盤後資料。
- 排名必須依原幣成交金額，而不是單純成交量。
- 顯示至少 20 檔個股。
- 不使用固定觀察名單冒充全市場排行。
- 資料不足、來源錯誤或授權未確認時，畫面應明確顯示無資料，不得補造排行。

### 2.2 成本與流量需求

- 不採付費行情方案。
- 不讓每台瀏覽裝置直接呼叫需要金鑰的來源 API。
- 避免將多裝置讀取流量轉成 Supabase PostgreSQL 或 Storage egress。

### 2.3 公開展示邊界

網站目前位於公開 GitHub Pages。即使實際使用者主要是本人、家人與朋友，只要任何人能從公開網址
取得行情，技術與授權判定上就不能視為只有 API 帳號持有人在私人裝置使用。

下列行為都可能落入第三方展示或再散布範圍：

- 將供應商回應加工成排行後放入公開網頁；
- 將 JSON 寫入公開 `data` branch；
- 將排行快照放入 public Storage bucket 或 CDN；
- 即使不收費，仍讓帳號持有人以外的人直接或間接取得資料。

「非商用」不等於自動取得公開展示權；仍須以來源的實際授權條款或書面答覆為準。

## 3. 目前專案實作需要的資料形狀

現行美股 collector 使用 Massive grouped daily aggregates 取得全市場 OHLCV，再以：

```text
估算成交金額 = 成交量 v × 成交量加權平均價 vw
```

計算全市場候選、排序並取前 20。來源必須至少提供：

- 股票代號；
- 交易日；
- 當日成交量；
- VWAP，或可合理替代的成交金額欄位；
- 收盤價；
- 用於日漲跌計算的基準價格。

API 如果只回傳「成交量最活躍的 20 檔」，即使每列另有價格，也不能據此產生全市場成交金額前 20。
高股價、成交量稍低的股票可能根本沒有進入候選集合，因此先取成交量前 20 再乘價格會得到錯誤排行。

現行品質門檻仍應保留：至少 20 列、名次連續、代號不重複、成交金額為正；任何一項失敗時，
workflow 應失敗且不得提交部分快取。

## 4. 候選來源比較

| 來源 | 免費功能與資料範圍 | 能否直接產出成交金額前 20 | 公開展示／再散布判斷 | 結論 |
|---|---|---:|---|---|
| Alpha Vantage | `TOP_GAINERS_LOSERS` 免費提供盤後 top 20 most actively traded | 否；官方沒有說明按成交金額排序 | 免費授權偏向私人、個人用途；未明確允許本案公開網站 | 只能作近似候選，不能直接採用 |
| Alpaca | most-actives 可按成交量或交易筆數取前 1～100 | 否 | 官方明確表示不能重新散布 Alpaca API 資料 | 不採用 |
| Twelve Data | 提供多種行情與市場資料 | 未找到符合本案的免費全市場成交金額排行 | Individual 方案禁止 redistribution；再散布需另訂協議 | 不採用 |
| TradingView Widget | 官方免費提供網站嵌入，保留預設品牌 | Heatmap 可按 `Price × Volume (Turnover)` 顯示，但不是可匯出的前 20 API | 官方產品即供網站嵌入，公開展示路徑最清楚 | 免費公開展示首選，但需改版型 |

### 4.1 Alpha Vantage

官方 `TOP_GAINERS_LOSERS` endpoint 會回傳美股 top 20 gainers、losers 與 most actively traded，
免費使用者預設取得盤後更新結果。

限制如下：

1. 文件稱為 most actively traded，沒有承諾依成交金額排序。
2. 回應如果只包含成交量最活躍的候選，無法回推全市場成交金額前 20。
3. 使用條款將一般授權描述為帳號持有人在自己擁有或控制的裝置上，作私人、非商業用途；
   本案公開網站及親友存取並非明確獲准情境。

若未來考慮使用，只能將功能誠實改名為「成交量最活躍前 20」，而且仍應先取得 Alpha Vantage
對公開親友網站的書面同意，不能把它當成目前「成交金額前 20」的等價來源。

### 4.2 Alpaca

Alpaca most-actives endpoint 可指定按成交量或交易筆數排序，最多回傳 100 檔；它不是成交金額排行。
此外，Alpaca 官方 FAQ 直接表示不能重新散布 Alpaca API data，因此不符合本案公開網站用途。

即使只做盤後，也不能因為資料不再即時就自行假定再散布限制消失。

### 4.3 Twelve Data

Twelve Data 的 Individual plans 用於個人或內部用途。官方說明明確列出不允許 redistribution，
任何再散布需要另行簽訂協議。因此免費／個人方案不能解決本案條款問題。

### 4.4 TradingView 官方 Widget

TradingView 將 Widgets 定位為可免費嵌入網站的元件，免費使用時需保留預設 TradingView 品牌。

相關能力：

- Stock Market Widget：顯示當日漲幅、跌幅及最活躍股票，但只有前 5 名。
- Stock Heatmap Widget：可將 Size by 設為 `Price × Volume (Turnover) 1D`，以金額活動排序與配置方塊。
- Screener Widget：可供使用者排序股票，但不保證輸出固定的成交金額前 20 契約。

限制如下：

1. TradingView 沒有提供可下載市場資料的公開 API。
2. Widget 資料不能下載、匯出或轉存成專案 JSON。
3. 美股 Widget 的 NASDAQ／NYSE／NYSE Arca 資料來自 Cboe One delayed stocks，與完整 SIP
   全市場成交量可能有差異。
4. 不能擷取 iframe 內容後重新產生自訂排行。
5. 必須保留官方品牌、連結及 Widget 本身的資料呈現方式。

這個方案的優勢是由使用者瀏覽器直接向 TradingView 取得 Widget，專案不保存及再發布原始行情；
也不使用 Supabase PostgreSQL、Storage 或 `data` branch，所以不會增加 Supabase 行情流量與儲存空間。

## 5. 建議方案

### 5.1 在「免費」與「可公開」不可放棄時

建議將美股原本的「成交金額前 20」區塊改成：

```text
美股成交金額熱度
資料來源：TradingView／Cboe One 延遲行情
```

呈現方式：

1. 嵌入 TradingView Stock Heatmap Widget。
2. Size by 使用 `Price × Volume (Turnover) 1D`。
3. Color by 使用當日漲跌幅。
4. 保留 TradingView 預設品牌與連結。
5. 使用 lazy loading，只有使用者切到美股總覽時才載入。
6. 不擷取、不解析、不代理、不快取 Widget 回應。
7. 不將 Widget 資料寫入 Supabase、`data` branch 或公開 CDN。

這是目前唯一查到「免費且本來就設計為公開網站嵌入」的可行路線，但產品需求必須從固定前 20
表格調整為成交金額熱度視覺化。

### 5.2 在「精確前 20」與目前自訂版型不可放棄時

維持目前 `turnoverLeaders` 契約及品質門檻，但在取得書面授權前：

- `MarketTurnoverCdn:Public` 維持 `false`；
- 不把美股排行寫入公開 `market-overview.json`；
- 不發布公開排行 CDN；
- 正式畫面繼續顯示資料尚未提供，不使用示意列補值。

接洽資料供應商時，必須取得以下問題的明確書面答覆：

1. 是否允許非商用公開網站向親友展示美股 EOD 行情？
2. 是否允許將原始資料計算成成交金額排行後公開？
3. derived data／derived ranking 是否仍受 redistribution 條款限制？
4. 是否允許快取到公開 Git branch、Storage bucket 或 CDN？
5. 允許保存多久，是否必須刪除歷史快取？
6. 是否限制使用者數、裝置數、頁面瀏覽量或地區？
7. 必須顯示哪些來源標示、延遲聲明與免責文字？
8. 書面許可是否包含 NYSE、NASDAQ、NYSE Arca 與 SIP／各交易所資料權利？

只有回覆明確涵蓋目前架構，才可啟用公開快取。單純取得免費 API key、App Key 或付費訂閱，
都不能自行推定已取得公開展示權。

## 6. 不建議的替代做法

### 6.1 用成交量前 20 乘上價格

這只會得到「成交量前 20 候選中的估算成交金額排序」，不是全市場成交金額前 20。除非來源先提供
足夠大的完整候選集合，否則結果可能漏掉高股價股票，不能沿用目前標題。

### 6.2 瀏覽器直接呼叫免費 API

- API key 會暴露在前端或被濫用。
- 每台裝置都會重複消耗配額。
- 不能解決公開展示／再散布問題。
- 多裝置結果可能因呼叫時間與配額不同而不一致。

### 6.3 將公開網站改成登入後顯示

登入只能控制誰看到，不能自動把第三方展示變成帳號持有人的私人使用。家人與朋友仍是其他使用者；
除非資料條款明確允許封閉群組展示，否則不能把登入當成授權替代品。

### 6.4 使用 Yahoo、交易所網站或其他未文件化 endpoint

未文件化端點可能隨時變動、封鎖或回傳 429，也沒有因此取得再散布權。這類來源不適合作為正式排行
的權威資料源，也不應繞過網站限制抓取後放進公開快取。

## 7. 實作交接條件

若採 TradingView Widget，後續模型或開發者應先取得使用者對「改成熱度圖、不再承諾固定前 20」的
明確確認，再進行程式修改。建議驗收條件如下：

- 美股總覽不再顯示空白的成交金額前 20 卡片。
- Widget 能在桌面與手機正常顯示。
- 標題不宣稱精確全市場前 20。
- 畫面明確標示 TradingView 與延遲行情。
- 保留 TradingView 預設品牌及連結。
- Network 不出現專案代理、擷取或重發布 Widget 行情的請求。
- Supabase PostgreSQL 與 Storage 沒有新增美股排行讀寫。
- `data` branch、`market-overview.json` 與 manifest 不包含從 Widget 擷取的排行。
- Widget 載入失敗時顯示來源暫時不可用，不回退到示意或舊排行。

若採授權 API，則除上述畫面正確性外，還必須驗證：

- 書面授權涵蓋 derived ranking、公開網頁與 CDN 快取。
- collector 的全市場候選完整，並通過現行品質門檻。
- 排名可由原始成交金額或 `volume × VWAP` 重算對帳。
- API 429／403／資料不足時 workflow 紅燈，且不提交部分快取。
- API key 只存在 GitHub Actions secrets，不出現在 repository、log 或前端。

## 8. 對日股／韓股的影響

本報告只處理 Massive 的美股替代問題。TradingView 目前公布的免費 Widget 亞太市場清單沒有列出
JPX／TSE 股票或 KRX 股票，因此不能據此取代日股／韓股的 KIS 排行來源。

日韓資料仍應維持獨立評估：KIS API 技術可用性與交易所公開展示權必須分開確認，不能因美股改用
TradingView Widget，就推定日韓也取得相同展示權。
