## 1. 目標、範圍與已確認決策

在既有熱絡指數旁回答「目前交易集中在哪、哪些股票／族群同向」：權值股主導、全面上／下、局部族群走強／弱、背離或方向未明。這是量價與廣度的觀察判讀，不宣稱計算每檔股票對指數的精確貢獻。

1. 用該交易日狀態分類，不要求前 20 日成交基準、跨日異常或回測才能算。選歷史日仍只用該日資料。
2. 權值觀察群 H20 保留「指數權重前 20 名」及當日固定身分；只需要知道成員，不要求每檔精確權重或發行股數。不能改成交前 20 名、0050 成分或以股價高低當權值。
3. 全面上／下需多數族群內多數股票同向，且權值之外也廣泛同向；不是要求每檔都漲／跌。
4. 漲跌互見、多空分歧、平盤整理合併為「方向未明」。
5. 上市、上櫃分開判斷；興櫃不混入這兩個市場。既有熱絡、排行榜、自訂價格、成交值公式保持原意。
6. ETF 僅為補充，不是分類主體；不研究法人怎麼操作 ETF。第一版普通股結構不把 ETF、TDR、權證、ETN、特別股當普通股加總。
7. 不改已確認名稱，不另造 0～10 分數，不擴大至下單、投資建議或買賣訊號。
8. 可從原始輸入重算的 H20 指標、成交占比、廣度及分類，不要求新建每日封存、basis 表、結果表或日檔。執行快取／CDN 輸出可沿用，但不能成為必須先有封存才分類的限制。
9. 盤中使用排行榜／自訂頁已採用的最終價格，即 `latest.json` 指向的同輪完整檔；不另外挑成交價、買賣中價或另一時點的價。盤後／歷史使用該頁該日的最終價與漲跌基準。
10. 收盤凍結、沿用價、估價或補洞價，仍按畫面同價推估；資料來源與真實時間可說明，不因價格年齡超過 10 分鐘就取消分類。
11. **所有已有行情的歷史日都必須有完整權值分類，並維持免費官方來源**。缺身分的一般分類是目前失敗處理行為，使用者未接受它作最終交付。驗收需逐日確認兩市場H20皆20檔、適用日期與來源可追溯，並以該日價量重算。

## 3. 輸入、價格與日期契約

### 3.1 必要輸入

| 輸入 | 口徑與用途 |
|---|---|
| Market、Ticker、股票類型 | 決定上市／上櫃普通股集合；同市場代號唯一。 |
| 最終價格、當日有效漲跌基準／日漲跌幅 | 共用既有 C# 還原權息與價格流程；來源與排行／自訂一致。 |
| 當日累計成交值 | 比較股票、H20、權值外與族群的成交集中程度；不是淨流入或買超。 |
| 族群身分 | 第一版沿用可驗證主分類，避免重疊題材重複加總造成假擴散。 |
| H20 成員身分 | 當日固定的 20 檔觀察群；不因當輪缺報換第 21 名。 |
| 官方指數日漲跌 | 指數方向與股票／族群方向比較；不反推個股精確貢獻。 |
| 日期、runId、行情時間、來源版本／hash | 防止混日混輪，說明真實時間；不因正常凍結時間較早而阻擋。 |

不要求 IssuedShares、全市場市值、StartWeight、RawPreviousClose 作精確指數重建。股票日漲跌仍需要有效基準；兩者不可混淆。

### 3.2 同價、同輪、歷史日

- 盤中 raw latest 是小型指標，價格在其 `file` 指向的完整快照。先載入排行／自訂目前同輪資料，再由 C# 使用相同欄位算結構；維持 runId／日期／完整 SHA256 校驗及競態防護。
- 盤後按選定日的原始行情與參考價重算；不能因沒有 `data/market-structure/YYYY-MM-DD.json` 就宣告該日無法分類。
- 目前族群性／H20 是否適用舊日須可解釋；不能無聲用今日身分改變歷史。若缺必要身分資訊，列出具體缺口與已能計算的部分，不要求回補歷史發行股數。
- 有行情列但缺價／日漲跌基準時列缺值；整列缺席不能悄悄縮小預期集合。H20 仍保持原成員，可從原始名單與資料重建，無須另存衍生名單。
- 標的來源為 LastTrade、PreviousTrade、BidAskMid、補洞或收盤凍結時，使用畫面同一最終價。價格來源可顯示，不能額外換價或單憑種類取消分類。
- 當前畫面跨日載入舊行情時維持日期提示，不把舊日期冒充今天。正常收盤最後價可繼續推估，不使用興櫃的新時間冒充上市櫃成交時間。

## 4. 計算指標與現行判讀方案

### 4.1 集合與共用公式

每市場定義 S 為該日預期普通股集合、H 為 H20、R 為 S 去除 H。以既有 C# 計算的日漲跌幅 r 判方向：高於中性帶為漲，低於負中性帶為跌，其餘平；缺值不補零。

~~~
Bup(A)   = A 上漲數 / A 有效漲跌數
Bdown(A) = A 下跌數 / A 有效漲跌數
M(A)     = A 有效日漲跌幅中位數
T        = S 當日成交值合計
C20      = H 成交值合計 / T
P20      = Σ(H 有效成交值 × r) / Σ(H 價格／基準有效的成交值)
Prest    = Σ(R 有效成交值 × r) / Σ(R 價格／基準有效的成交值)
~~~

A 可為 S、H、R。漲跌獨立計數，不能用 `1 - Bup` 推下跌。成交分母不受頁面成交門檻、排行篩選、觀察期間影響；成交累計不以預估收盤成交值替代。價格無效但成交存在時，可列成交分布，但不混入價格加權分母。零分母為 null。

每個族群 g 同時計算全體與去 H 的上／下／平數、同向比例、中位漲跌、成交占比及有效覆蓋；全面行情用去 H 資料確認多檔參與。多數族群比例 Gup／Gdown 由合格群的方向計數，分母不得因漏報變小。重疊題材成交值先對 Market＋Ticker 去重，不直接加總既有 FundScore／熱度分數。

### 4.2 分類依據

| 判讀 | 必要證據 |
|---|---|
| 權值走強／弱 | H20量價方向與成交集中、官方指數同向，以及R跟隨有限；允許單一真正大型權值主導，不硬要求12檔同向。 |
| 全面走強／弱 | R 多數股票同向，且多數合格族群內多檔同向；不能只由單一大股票或成交加權平均判全面。 |
| 局部族群 | 少數合格群有多檔同向，該群股票聯集具成交參與，尚未全面擴散。 |
| 背離 | 指數與 R／多數群反向，並有 H20 量價同向支持；只憑指數家數反向不能命名權值原因。 |

優先檢查有權值量價證據的背離，再全面、權值主導、局部；完整輸入但證據互相抵銷則方向未明。某種分類所需資料缺漏，只影響依賴它的判斷，不將全部已可用資訊抹掉。不得套舊 `CH / Dplus / Dminus / residual` 公式。

### 4.3 v2工程門檻與規則版本

最終規則版本 `market-structure-v2.1-price-breadth`、結果schema 2；所有公式集中C#，前端不重判。以下是可調工程預設，並非使用者逐項核准或投資訊號。

| 項目 | 現行條件 |
|---|---|
| 日漲跌中性帶 | 股票與指數均±0.10個百分點；嚴格超過才有方向。 |
| 合格族群 | 權值外至少5檔、有效日漲跌覆蓋≥90%；最少5個可比較群，覆蓋不足的群仍留在分母。 |
| 群方向 | 群內至少60%有效股票同向，且中位漲跌同向。 |
| 全面 | 權值外至少60%有效股票同向、中位數同向，且**嚴格過半**合格族群同向；不要求每檔都漲跌。 |
| 局部 | 未達全面，至少一個合格同向群，這些群成交占全市場≥10%；上下都有符合群則方向未明。移除舊30%～2/3無法分類區間。 |
| 權值主導 | 權值群成交占比≥35%、價格成交加權方向超過中性帶、至少1檔已知權值同向；官方指數同向，權值外同向比例上界≤45%及中位數未明顯跟隨。 |
| 背離 | 指數、權值群量價同向，權值外股票及多數群反向；缺權值證據不歸因權值。 |
| 真實必要覆蓋 | 全市場有效日漲跌≥90%、產業身分≥95%、合格群日漲跌≥90%、成交對應有效日漲跌≥95%。 |
| 成交集中副標 | 權值群成交占比≥50%；與分類35%條件用途不同。 |

相同輸入與規則得相同分類。只有價格／成交高的一檔普通股票不能冒充H20；一檔真正大型權值可以主導，但仍需指數、集中度及權值外廣度共同支持。缺身份時的保守界線見10.2節。

## 5. 品質、呈現與儲存取捨

- 保留重複代號、負數、日期／輪次錯誤、無有效漲跌基準、族群／H20 身分缺失及零分母檢查。
- 移除因缺股數、精確權重、估算指數貢獻殘差或正常最後價年齡造成的整市場不足。`stale_snapshot` 不能再單憑超過 10 分鐘判定最後價不可推估。
- 「有效報價」說明能比較的數量，與價格來源分開顯示；買賣揭示／補洞／凍結均沿用畫面同價。
- 股數 API 舊程式逾時的修復方向是移除股數依賴。仍需的族群／H20 身分來源可重試、備援或使用可驗證的既有分類資料，不能再下載整份股數表當必要條件。
- 畫面保留樣板 B 收合摘要、雙市場卡、H20 燈號、權值外廣度及明細；精確市值權重、指數貢獻、股數警語應隨新方案調整，顯示量價估算的真實用途。
- 呈現具體原因與缺項，不只截取「必要行情、權重或分類資料未通過品質檢查」第一句。尚未開盤與更新中是說明；價格凍結可保留分類與真實時間。
- 不預設新 DB 表、每日 basis／result archive 或付費權重來源。現有行情、參考價與股票分類資訊是原始輸入；衍生結果按需重算。
- CDN immutable 檔、latest、短期快取及規則／輸入 hash 可保留配送與防混輪用途；只有 hash 無法還原原始輸入，不能稱為所有早期輪次已精確重播。
- 較簡單的只在舊稿追加新說明會留下矛盾；本文件以新方案為主體，保留舊版失敗證據。診斷附表為交接文件，不是新增每日計算前置資料。

### 10.2 不完整H20的保守界線

已知k檔，未知u=20−k；未知成員必在尚未剔除的普通股中。

- 權值成交占比只顯示已知成交/T，標「至少」；已知權值平均漲跌明示是已知成員。
- 全面廣度以 `(同向家數−u)/(有效家數−u)` 的下界（最低0）判斷。合格同向群按使其失去多檔／60%方向資格的最小剔除成本排序，把u個未知成員以最壞方式分配；剩下群仍嚴格過半才稱全面。分母保守保留全部原合格群。
- 權值加權漲跌分子，以已知Σ(v×r)加上外部最負／最正u筆得上下界；分母下界為已知成交，上界為已知成交加外部最大u筆成交。按分子正負選保守除數。只有全部有成交股票具有效漲跌、方向界線與成交下界仍達標，才用權值證據。u=0時還原完整20檔。
- 權值外跟隨用同向比例上界 `同向家數/(有效家數−u)`（最高1），避免未知成員使「跟隨有限」誤成立。身分全缺時不能證明權值方向。

未知燈號以「？」顯示，包括已知0/20仍保留20格，不拿其他股票填格。整列缺席的0成交占位不是已知零成交，僅保留一般族群分類，不能確證權值成交集中；成交欄為可用行情占比。一般全面／局部可正常判讀，DataStatus=partial與盤勢方向分開呈現，不一律塗灰或丟棄說明。
