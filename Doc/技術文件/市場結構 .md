## 1. 產品目標與已確認範圍

在既有熱絡指數旁增加「市場結構」，回答：今天是權值股帶動、全面同向、局部族群表現，還是方向未明。成交值輔助確認交易集中程度，ETF 只作補充。

已確認需求：

1. 以當日行情判讀，不要求前 20 日成交基準、跨日異常偵測或歷史回測才能分類。昨收／當日參考價與當日適用權重是必要基準。
2. 權值群採指數權重前 20 名，當日名單固定，搭配成交值；不可改採成交前二十。
3. 全面上漲必須確認權值之外也在漲；全面下跌對稱處理。「全面」指多數有效族群及其成員廣泛同向，不要求全部標的。
4. 漲跌互見、多空分歧與平盤整理合併為「方向未明」。
5. 上漲、下跌各有權值、全面、局部族群狀態；指數與多數股票反向時有專用背離名稱。
6. 現有熱絡、排行、族群熱度公式保持原意，不新增另一個 0～10 分數、不產生買賣訊號或投資建議。
7. 成交值是成交活動，不直接解讀成淨流入、法人買超或特定交易者賣壓。

本文件取代 2026-10-02 舊稿的「C10＋20 日歷史中位數」主軸。第一版不做近 20 分鐘輪動、同時段歷史異常或 ETF 主導的分類總覽。

最新《台股資料》與程式的既有熱絡範圍已含興櫃。新功能的指數診斷仍分上市／上櫃，不把興櫃放進兩個指數權重；既有熱絡範圍不變。

第一版依當前實際程式更新本文件。公司 API 只有股數與產業資訊，沒有正式指數成分權重；故目前 H20 與指數貢獻明確標為估算，並以資料覆蓋和指數重建殘差作保守品質閘門。此版本沒有保存歷史 basis，也不回算歷史狀態；盤後只輸出最新日，符合先看當日市場集中方向的產品範圍。

## 2. 完整狀態契約

| 狀態碼（建議） | 顯示名稱（已確認） | 說明 |
|---|---|---|
| weight_led_up | 權值主導上漲 | 指數主要由權值群帶動，其他股票與多數族群跟漲有限。 |
| broad_up | 全面上漲 | 百花齊放：多數族群內多數股票上漲，權值之外也普遍上漲。 |
| sector_up | 局部族群走強 | 少數族群內多檔股票上漲，尚未擴及多數族群。 |
| weight_led_down | 權值主導下跌 | 指數主要被權值群拖累，其他股票與多數族群未普遍走弱。 |
| broad_down | 全面下跌 | 多數族群內多數股票下跌，權值之外也普遍下跌。 |
| sector_down | 局部族群走弱 | 少數族群內多檔股票下跌，尚未擴及多數族群。 |
| undirected | 方向未明 | 漲跌交錯、變化有限或證據分歧，沒有明確主導方向。 |
| weight_support_broad_down | 權值撐盤／多數族群下跌 | 權值帶動指數上漲，但多數族群及非權值股票下跌。 |
| weight_drag_broad_up | 權值壓盤／多數族群上漲 | 權值拖累指數下跌，但多數族群及非權值股票上漲。 |

背離名稱保留「多數族群」，不要自行改成「權值撐盤／全面下跌」。資料不足不是中性盤勢。

尚未開市、來源過期、計算更新中以資料狀態說明，不增加新的盤勢分類。C# 統一提供狀態碼、中文名稱、短句及證據；JS 不重新判斷。

## 4. 資料來源、範圍與當日 basis

### 4.1 每市場當日集合

上市 TWSE、上櫃 TPEX 各自計算：

- S：當日行情內可辨識的普通股，用於廣度、產業與成交分母。
- H20：以公司名冊發行股數 × 前收價估算市值排序的前 20 檔；同值以代號穩定排序。這是指數權值 proxy，不代表正式指數成分或權重。
- R：S 去除 H20，用來確認權值之外是否全面上漲／下跌。

估算 H20 使用原始前收而非盤中即時市值，因此同一市場同一交易日名單固定；不因當日成交排名、漲跌或即時市值換人。名冊／日期、價格或權值報價不足時，不以第 21 名替補，資料品質閘門會阻止可靠分類。

興櫃、ETF、TDR、權證、ETN、特別股不進上市／上櫃普通股廣度與 H20。ETF 不另立分類主軸。

第一版實際使用證交所與櫃買公司名冊的股數／產業欄位，**不是已證實的官方指數權重來源**。因此計算以股數 × 前收市值估 H20，結果和畫面都標示估算；用全市場加權報酬與官方指數漲跌比較殘差，超限即降為資料不足。取得授權的正式成分／權重來源後才能替換估算 basis。

不能直接使用：

- 0050／台灣 50 的成分權重或自由流通市值，代替加權指數權重。
- 「上市公司市值排行前二十名」整頁：本次搜尋內容有 ETF，先截二十再排除會不足二十。
- 公司名冊直接當指數成分，忽略新上市納入、變更交易方法、停牌／恢復及企業事件。
- 實收資本額除以 10 推股數；不同面額、特別股與 TDR 會出錯。

官方來源 API、欄位解析、日期與 hash 已接入；候選來源的欄位和覆蓋仍待真實交易日檢查。不得把普通股股數估算描述為正式成分權重，也不得改採成交前二十。

### 4.3 當日計算與日期保護

目前不保存當日 basis 到 `data` branch 或資料庫，亦不建立歷史 revision；使用者要先知道今天市場集中在哪。計算結果記錄當次來源名稱、來源日期、來源內容 SHA256、輸入 hash、規則版本及 basis hash，供結果追溯。

官方名冊日期晚於行情交易日、超過容許時效或市場來源讀取失敗時，該市場回報資料不足；不拿更新的名冊回填舊交易日。靜態頁只匯出最新盤後日，歷史日期不重算市場結構。

### 4.4 股票方向與估算指數貢獻分口徑

股票廣度／族群方向使用官方還原權息參考價；估算指數貢獻使用 MIS／盤後原始前收價，避免把還原後漲跌當成價格指數變化。全市場預估市值權重為「普通股股數 × 原始前收」，每檔當日原始漲跌率乘預估市值占比後加總，並與官方指數當日漲跌幅比較殘差。

這只是透明估算，不是交易所成分名單或官方指數貢獻；不包含正式自由流通因子、指數納入維護與企業事件調整。殘差超出候選上限就回報資料不足，不能把推算值稱為已驗證權值貢獻。股票方向與價格指數估算分開，避免現金股利的還原口徑混入價格指數。

## 5. 計算指標

比例存 0～1；漲跌幅與貢獻存百分點，1.0 表示 1%，不是 0.01。decimal 計算，分類前不四捨五入。

### 5.1 股票廣度

對有效價格與有效基準的還原後漲跌幅 r：

~~~
r > stockNeutralPct   -> up
r < -stockNeutralPct  -> down
其餘                  -> flat

Bup(A)   = A 上漲數 / A 有效價格數
Bdown(A) = A 下跌數 / A 有效價格數
M(A)     = A 的 r 中位數
~~~

A 分別取 S、H、R。上下跌獨立計數，不能用 1－Bup 推 Bdown。缺值另計；無成交但有官方有效價格／基準者可平盤，停牌依官方狀態處理，不以補零製造平盤。

### 5.2 權值量價與指數貢獻

~~~
T     = S 有效成交額合計
C20   = H 有效成交額合計 / T
P20   = Σ(H 有效 V × r) / Σ(H 有效 V)
Prest = Σ(R 有效 V × r) / Σ(R 有效 V)
W20   = Σ(H 日初權重)
~~~

分母不受畫面篩選、成交門檻或期間影響。缺價格的成交可進成交分布，但不能進價格加權分母，另記成交額價格覆蓋。零分母為 null。

目前第一版一律以普通股股數 × 原始前收估算市值占比，沒有直接官方成分權重：

~~~
q_i = (rawClose_i / rawPreviousClose_i - 1) × 100
weight_i = issuedShares_i × rawPreviousClose_i / Σ(issuedShares × rawPreviousClose)
c_i = weight_i × q_i                      // 百分點估算
CH  = Σ(H20 的 c_i)                        // 權值淨貢獻估算

Dplus  = Σ(H20 的 max(c_i,0)) / Σ(全市場的 max(c_i,0))
Dminus = Σ(H20 的 max(-c_i,0)) / Σ(全市場的 max(-c_i,0))
residualPct = 官方指數當日漲跌幅 - Σ(全市場的 c_i)
~~~

貢獻比例分母為零則 null；不除以指數淨點數。因完整上市／上櫃普通股市值是估算分母，不代表指數正式權重；缺股數／前收時品質閘門阻止分類，不把缺漏股數重新正規化。H20 成員保留估算市值占比、成交占比、價格反應與估算貢獻，不更換名單。

### 5.3 族群方向與擴散

第一版以當日交易所產業主分類計算擴散，同一市場每檔只歸一個主分類。現有重疊題材保留補充用途，不改 TopicMapping。

每分類 g，分別輸出全體與去除 H 的有效數、上／下／平數、比例、中位 r、成交額、最大成員成交占比、代表股票及覆蓋率。

全面行情用去除 H 的分類資料，確認權值之外廣泛同向。合格分類至少有 minGroupMembers 個預期可比較成員；分母由當日名冊固定，不能當輪漏報就縮小：

~~~
groupUp(g)   = Bup(g去H) >= groupBreadthRate 且 M(g去H) > stockNeutralPct
groupDown(g) = Bdown(g去H) >= groupBreadthRate 且 M(g去H) < -stockNeutralPct
Gup   = groupUp 數 / 預期合格分類數
Gdown = groupDown 數 / 預期合格分類數
~~~

小樣本／未分類／缺報分類另列。數個重疊題材合計成交時先取 Market＋Ticker 聯集；不直接相加 FundRawShare，不用 FundScore、CompositeScore 判斷漲跌。

### 6.2 共用條件

~~~
broadUp = Bup(R) >= broadStockRate
          且 M(R) > stockNeutralPct 且 Gup >= broadGroupRate
broadDown = Bdown(R) >= broadStockRate
            且 M(R) < -stockNeutralPct 且 Gdown >= broadGroupRate

weightUp = CH >= minWeightNetContributionPct
           且 Dplus >= weightContributionShare 且 P20 > stockNeutralPct
weightDown = CH <= -minWeightNetContributionPct
             且 Dminus >= weightContributionShare 且 P20 < -stockNeutralPct
~~~

P20 確認交易活動的價格方向；C20 只決定成交副標，不要求它高才可稱權值主導。Dplus／Dminus 高不能單獨證明狹窄，還要 R 與分類證據。

localUp：groupUp 至少一個、Gup 不超過 maxLocalGroupRate，成員股票聯集成交占 S 至少 localTurnoverShare。localDown 對稱。去 H 成員須證明多檔參與，明細仍列全體。不能一檔股掛十個題材就製造多族群走強。

### 6.3 固定判定順序

~~~
if 必要品質不通過:
    insufficient_data
else if 指數 > indexNeutralPct 且 broadDown 且 weightUp:
    weight_support_broad_down
else if 指數 < -indexNeutralPct 且 broadUp 且 weightDown:
    weight_drag_broad_up
else if broadUp 且 指數 < -indexNeutralPct:
    undirected + 指數股票反向但權值原因未確認
else if broadDown 且 指數 > indexNeutralPct:
    undirected + 指數股票反向但權值原因未確認
else if broadUp:
    broad_up
else if broadDown:
    broad_down
else if 指數 > indexNeutralPct 且 weightUp
        且 Bup(R) <= restDirectionCeiling 且 M(R) <= stockNeutralPct:
    weight_led_up
else if 指數 < -indexNeutralPct 且 weightDown
        且 Bdown(R) <= restDirectionCeiling 且 M(R) >= -stockNeutralPct:
    weight_led_down
else if localUp 且 !localDown:
    sector_up
else if localDown 且 !localUp:
    sector_down
else:
    undirected
~~~

全面行情優先於權值行情，避免普遍上漲仍因大權重被誤判。雙向局部同時成立，保留方向未明及兩側代表分類，不挑成交略多的一方硬決定市場方向。

背離按最後確認，需指數與股票確實反向；指數中性不自動稱撐盤／壓盤。沒有權值因果證據不得只憑家數反向命名。必要來源缺失為資料不足；完整資料但口徑／價格證據分歧可為方向未明並附原因。

## 7. 品質與失敗模式（第一版實際規則）

上市與上櫃分開計算；一邊資料不足不會改變另一邊結果。任一市場遇到重複代號／basis、負數、缺股數或價格覆蓋不足，都會回報「資料不足」，不會拿零值或第 21 名補位。第一版主要品質閘門如下，數值均屬候選門檻：

- 來源名冊日期不得晚於行情日，且距行情日不超過 7 個日曆日；盤中快照不得比計算時刻舊 10 分鐘以上或落在計算時刻未來 2 分鐘以上。
- 普通股股數與前收價格需完整，估算權重覆蓋至少 99%；權值群需恰有 20 檔。
- 行情報價至少覆蓋 90%，產業分類至少覆蓋 95%；可比較產業至少 5 個，合格產業報價覆蓋至少 90%。
- 成交額價格覆蓋至少 95%、成交額總和大於零；估算全市場漲跌與官方指數的殘差絕對值不超過 0.15 個百分點。
- `Market＋Ticker` 與來源 basis 必須唯一；缺值不補零。任一必要品質條件失敗，就不輸出方向分類。

實際 reason codes 由 C# 提供，包括 `missing_basis`、`basis_date_invalid`、`share_coverage_low`、`weight_basis_coverage_low`、`index_price_weight_coverage_low`、`index_reconstruction_failed`、`quote_coverage_low`、`industry_coverage_low`、`group_coverage_low`、`group_quote_coverage_low`、`price_turnover_coverage_low`、`zero_turnover`、`weight_group_incomplete`、`stale_snapshot` 等。官方指數成分權重尚未接入，估算警語會與正常分類一同輸出。

盤中計算／發布例外由獨立 consumer 記錄並重試，不攔 raw 或 topic；同輪可發布「資料不足」，讓前端不會把舊輪次分類當成最新結果。必要 Supabase 連線缺失時 consumer 無法取得 advisory lock，raw 收集仍獨立處理。

## 8. 結果契約（第一版實際 JSON）

`MarketStructureResult` 為頂層物件，包含 `schemaVersion`、`rulesVersion`、`rulesHash`、`inputHash`、`basisHash`、`tradeDate`、`capturedAt`、`mode`、`industryVersion`、`isEstimated`、`runId`、`calculatedAt`、`twse` 與 `tpex`。每市場輸出 `statusCode`、中文 `displayName`／`explanation`、`dataStatus`、`reasonCodes`、`warnings`、指數變化與估算殘差、覆蓋率、權值成交占比、權值漲跌與估算貢獻、全體／權值／非權值廣度、產業方向、固定 H20 明細及判定 evidence。

未定義數值輸出 `null`；來源 hash、規則 hash 和輸入 hash 用來追溯單次計算。結果不含 basis revision、正式成分權重或歷史狀態容器。日期、模式與 run id 由 C# 計算服務提供；JS 僅呈現狀態與數字。未知 schema／狀態不能降級成方向未明。

## 9. 盤後單日輸出

盤後從本機／CI 目前可用的日行情中選最新交易日，並以當日還原參考價與上一有效收盤價計算股票方向；上一日價格只是當日漲跌所需基準，不會用多日資料計算規律、校準分類或重算舊日狀態。公司名冊日期若比行情日新或超出規則容許日數，會保守回報資料不足。

靜態 export 只輸出 `data/market-structure/latest.json`，manifest 描述其相對路徑、交易日、盤中 CDN 與規則版本。歷史日期選擇器不會顯示或計算市場結構，網站不持久化舊日 basis／分類結果，也不以最新名冊回填歷史。既有熱絡及排行歷史不變。

## 10. 盤中：獨立背景 consumer 與小型 CDN

### 10.1 worker 行為

1. `Program.cs` 啟動獨立 worker；只有 raw 完整快照成功發布才非阻塞 `Signal`。bounded Channel 容量 1、DropOldest，不 await 計算。
2. 啟動時由 raw CDN `latest.json` 讀回今日已發布快照，追最新可用輪次；不補全部盤中歷史。
3. 每次計算讀同一輪 raw snapshot 與當日公司股數／產業 basis。basis client 成功快取 8 小時，來源失敗快取 15 分鐘，避免每輪重抓。
4. 使用 raw 的上市／上櫃普通股、指數、還原參考價、原始昨收、預估成交值及價格來源；興櫃、ETF 與 TDR 不進此指數判讀。
5. 使用 `pg_try_advisory_lock(hashtext('frank-invest.intraday-market-structure'))` 作獨立 session lease；不新增資料表、DDL 或 Management 權限。無 lease 時不發布。
6. 輸入、basis hash、規則 hash 與 run id 放入結果；重試同一 raw 時結果可追溯。
7. 計算／發布例外不阻塞 raw／topic；保留待處理輪次，最多每 30 秒重試，若有更新輪次則優先新輪。停止時釋放 lease。
8. 資料不足結果仍可隨同輪發布，避免前端永久顯示舊成功狀態；所有來源都標示估算，沒有官方權重時不冒充實際指數貢獻。

### 10.2 Storage 契約與順序

沿用現有公開 bucket、秘密讀取及上傳基礎，不建立新 bucket／table：

- 完整檔：`intraday-structure-{yyyyMMdd-HHmm}-run{runId}-{rulesHash前8碼}-{basisHash前8碼}.json`。
- 小型指標：structure-latest.json。
- 指標含 schemaVersion、runId、tradeDate、capturedAt、file、contentHash、rulesVersion、basisHash。

先完整檔後指標；完整檔一年 immutable 快取，latest 十秒短快取。沿用有限保留／清理，且不能刪除 latest 所指檔案。發布前後都核對 raw latest run 與結果日期；較舊 run 不倒退覆寫新結果。

前端只接受指標 `runId`、交易日、日期時間和畫面目前載入的 raw run 全部相符，下載完整檔後再驗 SHA256 及結果內 run id。正在載入更新輪次時顯示等待；不拿舊結構解釋新 raw。

盤中 CDN 指標不當長期歷史資料庫；盤後靜態輸出只保存最新日，不建立歷史結果資料庫。

已讀 Supabase changelog 與 [CDN](https://supabase.com/docs/guides/storage/cdn/fundamentals)、[Smart CDN](https://supabase.com/docs/guides/storage/cdn/smart-cdn)。實作者仍需驗證實際 Storage 權限；禁止把 secret／Management token／密碼放前端。

## 11. 畫面、載入與 ETF 補充

### 11.1 摘要卡與證據

摘要區直接增加「市場結構」卡，分上市與上櫃，不平均兩個指數，也不改既有熱絡分數。每一市場呈現 C# 狀態名稱與說明、指數漲跌、權值前 20 成交值占比、權值外上漲比例、上漲族群比例、H20 淨貢獻估算，以及必要品質警語。

權值名單使用原生 `details` 收合，列代號／名稱、還原漲跌及成交值占比；固定名單不因排序改變。分類結果不使用顏色以外的暗示，狀態以文字呈現；「方向未明」與「資料不足」有不同樣式與說明。手機以自適應兩欄卡片顯示，權值清單可直向瀏覽。

第一版沒有第三個族群成員明細表、沒有可排序完整指數貢獻表，也沒有另做鍵盤排序控制；只輸出計算器已提供的摘要。所有數字和標籤均格式化自 C# 結果，不在 JS 重判。

### 11.2 相容與請求控制

- 舊 manifest 無設定，不請求不存在檔案；本卡隱藏或提示尚未提供，既有排行正常。
- 日期切換／盤中輪次切換使用 request sequence 防止晚回的舊結果覆寫新畫面，並嚴格校對 tradeDate、runId 與 capturedAt。
- 指標／immutable 完整檔 hash 或結果 identity 不符就拒絕顯示；DB fallback 沒有同輪結果時不拿別輪或盤後結果冒充。
- 舊 manifest 沒有市場結構 descriptor 時不請求不存在的 close 檔或 CDN；既有排行照常顯示。
- 前端只格式化／排序；不重新計算門檻、廣度、貢獻、百分比或主狀態。
- 尚無盤後結果時不建立舊日分類；載入中的同輪以「正在等待這一輪行情的分類結果」明示。

### 11.3 ETF

ETF 不進普通股廣度、權值估算、指數貢獻或盤勢分類；第一版不顯示 ETF 成交比，也不把 ETF 當成分類主體。這保留使用者確認的權值股與多數族群方向為核心，且不需要法人／申購買回資料。
