# 美股－熱絡指標

> 日期：2026-09-09
>
> 狀態：**修正規劃已整理，尚未改 Code、尚未發布**
>
> 範圍：市場切換頁的 11 檔美股類股 ETF 熱絡分數與方向資訊；不延伸為買賣訊號或投資建議

## 一、結論

2026-09-09 查核的公開快照約 2.4 分，前端顯示與現行公式相符；問題不在前端，而在公式把「多空方向」混進
「活躍程度」。下一版應把熱絡分數改為只衡量市場有多活躍，使用每檔 ETF 相對成交額與絕對波動；
上漲／下跌／平盤比例另外顯示，不再影響熱絡分數。股票成交額仍保留
`收盤價 × 成交股數`，基準改用目標日前 20 個完整交易日，絕不包含目標日自己。

本文件是計畫，不代表目前網站已套用新公式。

## 二、目前實作與已確認問題

目前資料流為 Yahoo Finance chart API（`range=2y&interval=1d`）→
`YahooFinanceDailyQuoteClient` → `MarketOverviewCalculator` → `market-overview.json` → 前端。

現行計算：

```text
breadthScore = (漲跌幅 >= 0 的檔數 / 有效檔數) × 10
volumeRatio  = 當日 11 檔成交額合計 / 各檔最近 20 日成交額平均的合計
volumeScore  = clamp((volumeRatio - 0.5) / 1.0 × 10, 0, 10)
heatScore    = 50% × breadthScore + 50% × volumeScore
```

已由程式確認的問題：

1. **方向與熱度混在一起。** 上漲家數占一半分數；若市場猛烈下跌但成交爆量，活動很強，
   熱絡分數仍最多接近一半。反過來，無量普漲也可能因上漲家數先拿到高分。
2. **平盤被算成上漲。** 判斷使用 `change >= 0`，`0%` 不是中性。
3. **基準包含當日。** `TakeLast(20)` 同時拿目前日，極端成交額會抬高自己的平均值，
   壓低相對量能。
4. **先加總再比較造成規模偏差。** 高成交額 ETF 對總量比的影響遠大於其他 ETF；
   分數沒有真正回答「多少個類股同時變活躍」。
5. **畫面 weight 並非市值權重。** 現行 weight 是近 20 日平均成交額占比，只能稱
   「資金關注度」，不能稱市場市值權重。

股票的 Yahoo `volume` 是成交股數，因此 `TradingValue = close × volume` 是可保留的近似成交額；
這點與加密貨幣的資料語意不同，不能共用同一個假設。

## 三、新指標的語意

固定原則：

- `heatScore` 只回答「今天相對近期正常水準有多活躍」，0～10 分。
- 漲跌方向不進 `heatScore`；另輸出 advances、declines、flat 與平均／中位漲跌幅。
- 每檔 ETF 先和自己的歷史比，再做等權聚合，避免絕對成交規模支配市場總分。
- 目標日必須是已收盤的美股交易日；基準固定為它之前 20 個完整交易日。
- 缺少目標日或不足 20 個基準點時回傳 `null`／warning，不拿更早的「最近值」冒充。

建議第一版公式如下，係數在實作前要用歷史資料回放確認：

```text
turnover(i,t)       = close(i,t) × volume(i,t)
turnoverRatio(i,t)  = turnover(i,t) / median(turnover(i,t-20 ... t-1))
absReturn(i,t)      = abs(close(i,t) / close(i,t-1) - 1)
volatilityRatio(i,t)= absReturn(i,t) / median(absReturn(i,t-20 ... t-1))

scale(r)            = clamp((r - 0.5) / 1.0 × 10, 0, 10)
activity(i,t)       = 50% × scale(turnoverRatio) + 50% × scale(volatilityRatio)
heatScore(t)        = median(activity(i,t) for all valid ETFs)
```

選中位數是為了讓單一類股的事件日不把全市場分數拉滿；每檔 ETF 在聚合時權重相同。若回放證明
中位數對「少數重大類股同時爆量」過鈍，可比較 trimmed mean，但不能退回絕對成交額加權。
`scale()` 暫時沿用現行 0.5 倍＝0 分、1 倍＝5 分、1.5 倍＝10 分的可理解區間；
這是待回測參數，不應在未看分布前宣稱已定案。
任一歷史中位數分母小於或等於 0 時，該分量應回 `null` 並產生 warning，不用任意 epsilon
製造一個看似精確的高分。

方向欄位另算：

```text
return > 0  => advance
return < 0  => decline
return = 0  => flat
```

可顯示 `上漲 A／下跌 D／平盤 F` 或方向比例，但不得再加回熱絡分數。這樣「爆量大跌」會是
高熱度＋偏空，「無量普漲」則是低熱度＋偏多，兩個維度不再互相污染。

## 四、資料與 UI 邊界

- Yahoo chart API 沒有正式 SLA；單檔缺資料照現行方式產生 warning，不以假值補齊。
- 美股 workflow 在 20:30 ET 後執行，應選最新已收盤交易日；週末／休市日沿用最近完整交易日，
  但同一張快照內所有 ETF 必須對齊同一 target date。
- 熱力圖大小若繼續使用平均成交額占比，文案只能是「資金關注度」；計算視窗也應改成
  target 前 20 個完整交易日，不含 target。若產品要顯示真正市值權重，必須另接有成分與市值
  語意的資料源，不可改標籤假裝 Yahoo 成交額就是市值。
- 活躍度與方向應各自帶 `asOfDate`、有效樣本數及 warning；前端不可在資料不足時顯示 0 分，
  因為 0 代表確定冷清，`null` 才代表不知道。

## 五、必要測試與驗收

| 情境 | 預期 |
|---|---|
| 全面大跌但成交額與絕對波動都顯著放大 | 高熱度、方向偏空 |
| 多數 ETF 小漲但成交清淡、波動很小 | 低熱度、方向偏多 |
| 漲跌幅恰為 0 | 計入 flat，不算 advance |
| 目標日爆量 | 目標日不得進自己的 20 日基準 |
| 單一 ETF 極端爆量，其餘正常 | 中位數聚合不應被單檔拉滿 |
| 成交額或絕對波動的歷史中位數為 0 | 對應分量為 null 並輸出 warning，不除以 0 或自行補 epsilon |
| 某 ETF 缺目標日 | 不往回拿舊日冒充；降低有效樣本並輸出 warning |
| 少於 20 個完整基準日 | heatScore 為 null，不用短視窗偷算 |
| 股票成交量 1,000、收盤 20 | 成交額使用 20,000，確認股票仍採 close × shares |

回放至少應涵蓋正常日、FOMC／CPI 高波動日、急跌爆量日、低量上漲日與休市前後。驗收不是只看
分數「像不像」，而是確認排序、方向分離、日期邊界與基準排除都符合上述不變條件。
