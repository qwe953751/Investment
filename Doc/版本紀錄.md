# 版本紀錄與跨裝置交接

這份文件是其他電腦、手機或 AI agent 接手時的第一個版本入口。
它記錄已發布的功能、Git 提交、資料庫 migration、驗證結果與下一步；完整公式仍以
[README.md](../README.md)、進度以[完成進度.md](完成進度.md)、未完成討論以 [TODO.md](../TODO.md) 為準。
其他裝置接手時的起手步驟已獨立成 [裝置接手流程.md](裝置接手流程.md)。

## 更新規則

- 每一則紀錄都要寫**詳細說明**：改了什麼、為什麼要改、怎麼驗證、目前是否已發布——不能只
  寫一行摘要帶過，之後的人（或另一個裝置的 AI agent）要能靠這則紀錄接手，不用回頭問。
- 標題格式固定為 `## [時間][裝置][更新標題]`，例如
  `## [2026-09-01][Mac][ETF 行情與資產帳戶整合]`。
- 「裝置」只能是下列四個值之一，不能自創新名稱：
  - `Mac`：家裡主機。
  - `手機`：路上直接在手機上操作，不是指「用手機測試網頁寬度」這種驗證動作。
  - `CodeX`：公司電腦上的 AI agent。
  - `裝置不詳`：從內容判斷不出是哪個裝置時，寧可標這個，不要用力猜。

  多一顆是多餘的。直接刪掉 `index.html` 裡的淺色按鈕；`applyTheme`／`wireThemeSwitcher`
  本來就是用 `querySelectorAll('.theme-switcher-option')` 泛用寫的，沒有寫死三顆，拿掉
  一顆不用動 JS 邏輯。

  直接掛在 `<td>` 上、又設了 `display: grid` 疊漲跌幅與盤中／盤後兩行文字——`display: grid`
  會讓這顆儲存格脫離表格原本的儲存格版面配置，量出來比同一列其他 `<td>` 矮了 5px，
  看起來像沒對齊。改成拿掉 `<td>` 上的 `display: grid`，讓它維持正常的 `table-cell`，
  改用兩個子元素（`<span>`、`<small>`）各自 `display: block` 疊行，視覺效果不變，

  「可以換行」，換行後使用者覺得占的寬度還是太多，壓縮到數字欄位的空間。加上
  `max-width: 110px`，讓自動表格版面把多出來的寬度讓給其他欄位。
