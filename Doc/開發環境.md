## 裝置分工

**這台 Mac 是主力機**，其他裝置是輔助。原因不是偏好，是有幾件事只在這台做過：

| 只在 Mac 上有的東西 | 為什麼重要 |
|---|---|
| `~/.zshrc` 裡的 `SUPABASE_DB_URL` 與 `SUPABASE_ACCESS_TOKEN` | 沒有這兩個就不能同步、備份、貼資料表定義 |
| GitHub 的 SSH key | `origin` 用的是 `git@github.com:` |
| 已經回補好的 `data/imports/`（304 天，約 20 MB） | 新裝置可以從 `data` 分支取，不必重抓 |

**好消息是：日常運作完全不需要任何裝置開機。**
每天的回補、同步、備份、發佈都在 GitHub Actions 上跑。
輔助裝置要做的只有「改程式碼」跟「看網站」。

## 必裝（不裝就不能改程式碼）

| 東西 | 版本（Mac 上實際跑的） | 怎麼裝 |
|---|---|---|
| Git | 2.39.5 | macOS 內建 / Windows 裝 Git for Windows |
| .NET SDK | **10.0.302**（`net10.0`） | <https://dotnet.microsoft.com/download> |
| GitHub CLI (`gh`) | 2.97.0 | `brew install gh` / `winget install GitHub.cli` |

驗證裝好了：

```bash
dotnet --version    # 要是 10.x
git --version
gh auth status      # 要顯示已登入 qwe953751
```

編輯器建議 **VS Code + C# Dev Kit**。用 Visual Studio、Rider 也可以，
專案是標準的單一 Solution（`Invest.sln`），沒有任何 IDE 專屬設定。

## 選配（什麼時候才需要裝）

這些**不裝也能改程式碼並推上去**，只有要在本機做特定事情時才需要：

| 東西 | 只有在你要做這件事時才需要 | 怎麼裝 |
|---|---|---|
| `libpq`（提供 `pg_dump`） | 在本機備份 Supabase | `brew install libpq` |
| `jq` | 把 `db/*.sql` 貼進 Supabase | `brew install jq`（Mac 內建 1.7.1） |
| `python3` | 在本機預覽匯出的靜態網站 | Mac 內建 3.11 |
| Docker | 在本機試還原備份（週日的 workflow 已經自動做了） | Docker Desktop |

**不需要 Node.js。** 前端只有一份手寫的 `site.js`，沒有 npm、沒有建置步驟。

`pg_dump` 有個雷：Mac 上 `brew install libpq` 不會把它放進 `PATH`
（這台的實際位置是 `/opt/homebrew/Cellar/libpq/18.6/bin/pg_dump`）。
備份腳本會自己去 Cellar 找，所以不必手動加 `PATH`；
真的要指定就設環境變數 `PG_DUMP`。
**pg_dump 的版本不能比 Supabase 舊**（Supabase 是 PostgreSQL 17.6），
比較新沒問題，比較舊會直接 `exit 1` 拒絕匯出。

## 環境變數

| 變數 | 給誰用 | 哪裡拿 | 沒有的話 |
|---|---|---|---|
| `SUPABASE_DB_URL` | `sync` / `verify` / `status` / `intraday` / 備份腳本 | Supabase 專案 → Settings → Database → Connection string（寫入帳號 `invest_writer`） | 這幾個指令直接報錯，其他功能正常 |
| `SUPABASE_ACCESS_TOKEN` | 貼 `db/*.sql` 用的 Management API | Supabase → Account → Access Tokens | 只影響建表，不影響日常 |
| `PG_DUMP` | 備份腳本 | 選配，指定 `pg_dump` 的絕對路徑 | 腳本自己找 |
| `INTRADAY_SOURCE` | 盤中收集器標記來源 | 選配，預設是機器名稱 | 用機器名稱 |

Mac 上這兩個放在 `~/.zshrc`：

```bash
export SUPABASE_DB_URL='[連線字串]'
export SUPABASE_ACCESS_TOKEN='[token]'
```

**這兩個值不在 repo 裡，也永遠不要放進 repo。**
`appsettings.json` 裡那組 Supabase URL 與 anon key 是**故意公開的**：
anon key 只有 select 權限（見 `db/001_intraday.sql` 的 RLS），
而且它會被發佈到 gh-pages，任何人都看得到，藏起來沒有意義。

`SUPABASE_ACCESS_TOKEN` 約 **2026-09-15** 到期（TODO 6 在追）。

## 需要哪些權限

| 權限 | 用途 | 怎麼確認有沒有 |
|---|---|---|
| GitHub repo `qwe953751/Investment` 的 write | 推程式碼、推 `data` 與 `gh-pages` 分支 | `gh repo view qwe953751/Investment` |
| GitHub SSH key（或改用 HTTPS + token） | `origin` 是 `git@github.com:qwe953751/Investment.git` | `ssh -T git@github.com` |
| GitHub Actions 的 secret `SUPABASE_DB_URL` | CI 連資料庫 | `gh secret list` |
| Supabase 專案 `dehzxlxyfvtnylwgbmqy` | 看資料、改資料表 | 登入 Supabase 後台 |
| GitHub Pages 已開在 `gh-pages` 分支 | 網站發佈 | 打得開 <https://qwe953751.github.io/Investment/> |

新裝置若不想設 SSH key，可以改用 HTTPS：

```bash
git remote set-url origin https://github.com/qwe953751/Investment.git
gh auth login          # 選 HTTPS，讓 gh 幫 git 記憑證
```

## 第一次在新裝置上開工

```bash
git clone git@github.com:qwe953751/Investment.git
cd Investment

dotnet build
dotnet test            # 應該是 36 個測試全過
```

到這裡就能改程式碼了。**下面幾步只有想在本機看到畫面才需要。**

取現成的行情快取（比重抓快非常多，重抓 300 天要好幾小時）：

```bash
git clone -b data git@github.com:qwe953751/Investment.git data-branch
mkdir -p data
cp -R data-branch/imports data/
```

或是自己回補（每次請求間隔 3 秒，70 個交易日約 15 分鐘）：

```bash
dotnet run --project src/Invest.Web -- backfill 300
```

啟動互動網頁（排行頁在 `/trading-value-ranking`，Terminal 會印出網址）：

```bash
dotnet run --project src/Invest.Web
```

匯出並在本機預覽靜態網站：

```bash
dotnet run --project src/Invest.Web -- export publish/site
python3 -m http.server 5199 --directory publish/site
```

`.claude/launch.json` 裡已經定義好這兩個（`invest-web` 用 5188、`static-site` 用 5199）。

## 指令一覽

```bash
dotnet run --project src/Invest.Web -- backfill [交易日數] [起始日期]
dotnet run --project src/Invest.Web -- export   [輸出目錄]
dotnet run --project src/Invest.Web -- intraday [--loop]
dotnet run --project src/Invest.Web -- sync     [保留交易日數]
dotnet run --project src/Invest.Web -- verify
dotnet run --project src/Invest.Web -- status   [來源] [輸出檔]
dotnet run --project src/Invest.Web -- curve

scripts/publish-gh-pages.sh publish/site
scripts/backup-supabase.sh [快照目錄]
```

需要 `SUPABASE_DB_URL` 的是：`intraday`、`sync`、`verify`、`status`、`backup-supabase.sh`。

## 分支規則

| 分支 | 放什麼 | 規則 |
|---|---|---|
| `main` | 原始碼 | 日常都在這裡，沒有在用 PR 流程 |
| `data` | `imports/`（行情快取）、`snapshots/`（備份）、`STATUS.md` | **只增不減。** 要刪任何交易日都得先確認 |
| `gh-pages` | 靜態網站 | 每次發佈都是全新的 orphan commit 覆蓋整支，不留歷史 |

`data` 與 `gh-pages` 都由 GitHub Actions 自己推，**平常不要手動動它們**。
`gh-pages` 一份快照就一百多 MB，不要 clone 它。

`origin` 上還留著兩個沒清的舊分支（`agent/fix-intraday-collection`、
`feature/daily-snapshot-automation`），可以忽略。

## 各裝置做得到什麼

| 裝置 | 改程式碼 | 本機跑網頁 | 本機備份 | 看網站 |
|---|---|---|---|---|
| 這台 Mac | ✅ | ✅ | ✅ | ✅ |
| 其他 Mac / Windows / Linux | ✅ 裝好 .NET 10 就行 | ✅ 需要行情快取 | 需要 `SUPABASE_DB_URL` 與 pg_dump ≥ 17 | ✅ |
| iPad / 手機 | 只能用 GitHub 網頁版改文字檔 | ❌ | ❌ | ✅ |

**改完程式碼要記得的事：** 只要動到畫面或計算，
就得重新 `export` 並發佈，否則手機上看到的還是舊的。
不想在本機做的話，推上 `main` 之後到 Actions 手動觸發 `每日排行快照`
（`workflow_dispatch`，可以指定只回補幾個交易日）也會順便重新發佈。

## 常見雷

| 症狀 | 原因 |
|---|---|
| `找不到環境變數 SUPABASE_DB_URL` | 沒設，或設在別的 shell profile |
| `pg_dump: server version mismatch` | 本機 `pg_dump` 比 Supabase（17.6）舊 |
| 排行頁一片空白、說資料不足 | 沒有行情快取，先取 `data` 分支或 `backfill` |
| 手機上看到舊資料 | 沒有重新發佈；或按一下標題旁的「檢查更新」 |
| 改了 `CollectionSchedule` 的時間但排程沒變 | cron 寫在兩支 YAML 裡，讀不到 C#，要手動改（TODO 8 未決） |
| `dotnet test` 找不到 SDK | 裝的是 .NET 8/9，這個專案要 10 |
