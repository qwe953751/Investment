## 排程 Action

目前有 7 條會自動重複執行的 GitHub Actions，涵蓋台股、美股、日股、韓股、月營收與備份還原。
`intraday.yml` 與日韓盤中流程都是自走鏈；YAML cron 只作斷鏈時的復原火種。

| Workflow | 觸發方式 | 實際執行時間（台北） | 做什麼 |
|---|---|---|---|
| `intraday.yml`（台股盤中） | 自走鏈；cron 為復原備援 | 交易日 08:40～13:35，每約 2 分鐘一輪 | 探測並收集 MIS，完整快照寫 Supabase |
| `daily-snapshot.yml`（台股盤後） | cron 進場後等待收盤；兩場備援 | 交易日 18:00 起，最晚重試至 21:00 | 回補、同步、備份、export 並發布網站 |
| `us-daily-snapshot.yml`（美股） | cron 後等待資料落地 | 工作日 10:30 起 | 回補美股觀察清單與市場總覽，檢查新鮮度 |
| `asia-market-overview-daily.yml`（日韓盤後） | 週一至週五 UTC 07:45（台北 15:45）進場，等待至台北 17:30 | 交易日 17:30 起 | 回補日股／韓股兩年日線；核心資料不全時 workflow 失敗且不提交部分 `data` 快取 |
| `asia-market-overview-intraday.yml`（日韓盤中） | 台北 07:45 cron 加 08:15／11:30 復原火種，自走接力 | 台北 07:50～14:35，每 5 分鐘一輪；東京交易時段 09:00～11:30、12:30～15:30（換算台北 08:00～10:30、11:30～14:30），首爾 09:00～15:30（換算台北 08:00～14:30） | 只收指數、風險值與 11 個產業代表，寫入獨立 Supabase Storage CDN，不寫 Postgres |
| `revenue.yml`（月營收） | 公告期密集、其後每天一次 | 台北 09:20～21:20（公告期）或 19:20 | 抓月營收，只寫資料庫 |
| `restore-test.yml`（備份還原測試） | 每週 cron | 週日 08:00 | 還原最新備份並驗證 |
