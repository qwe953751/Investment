## 踩過並且已經解掉的坑

這一節是給另一台裝置的：這些問題**已經修好了**，
但如果之後看到類似症狀，先回頭看這裡，不要重新debug一遍。

| 症狀 | 真正的原因 | 怎麼解的 |
|---|---|---|
| 排程說 18:00 卻 18:31 才動 | GitHub cron 是盡力而為，實測誤點 31（盤後）與 88（盤中）分鐘 | 提早排在非整點非半點卡住 runner，程式自己睡到目標時間 |
| 國定假日整條線紅燈 | 休市與「還沒公布」從 API 看起來一模一樣，都是空的 | 接官方休市日曆，**只用於降級** |
| 休市日曆把交易日判成休市 | 那份清單混著「春節前最後交易日」這種**照常開市**的日子 | 過濾掉名稱含「交易日」的列；拿 320 天快取交叉驗證過，零誤判 |
| 成交值跟玩股網差很多 | 官方成交金額含零股、盤後定價、鉅額交易 | 另抓七份報表逐檔扣除；台積電單日差過 59 億，足以改名次 |
| 盤中收集器整天沒寫入卻不報錯 | HTTP timeout 太短，個股清單抓不到就整場停擺 | 加長 timeout 並補上清單備援 |
| 手機看到的還是舊資料 | Pages 快取十分鐘且無法改標頭 | 網址帶 `?v=發佈時間`，`manifest.json` 用 `no-store` 讀 |
| 匯出的整包撐不住 | 資料檔連顯示文字都先算好，單檔快 1 MB | 只留數字、顯示格式交給前端，單檔剩四分之一 |
| `pg_dump: server version mismatch` | runner 內建 16，Supabase 是 17.6，版本不合直接 exit 1 | 掛上 pgdg 套件庫裝 17 |
| 裝了 17 還是回報 16.14 | `/usr/bin/pg_dump` 是 pg_wrapper，runner 上有 16 的預設 cluster 就照那個挑 | 直接把 `/usr/lib/postgresql/17/bin/pg_dump` 交給備份腳本（`PG_DUMP`） |
| 同步／對帳／心跳全部 `28P01` | GitHub Secret 裡的資料庫密碼過期 | 重設 `SUPABASE_DB_URL` |
